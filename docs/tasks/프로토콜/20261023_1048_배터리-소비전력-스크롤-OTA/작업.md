## 목표와 범위

은수님의 2026-10-23 요청에 따라 Android 리모콘에서 외부기 배터리 전압과 평균 전류를 읽어 소비 전력(W)을 표시한다. 메인 화면 전체를 세로 스크롤로 바꾸고 OTA는 버튼으로 펼치고 접는다. 상태 정보를 읽을 수 있게 유지한다. 기존 FF3 구현과 사용자 IDE 변경은 보존한다. 펌웨어/Python 프로젝트는 규격 확인만 하며 수정하지 않는다. 이번 작업의 커밋/푸시는 요청받지 않았다.

## 수용 기준

1. 기존 8바이트와 전류 포함 15바이트 이상의 배터리 값을 정확히 해석한다. 부호/단위/전류 상태/샘플 나이를 확인하고 무효를 0으로 표시하지 않는다.
2. 지원 옵션 비트맵이 확인된 장치에서만 기존 2초 감시 주기에 배터리를 조회한다. OTA/FF3 처리/세대 판별/다른 송신 중에는 끼어들지 않는다. 구형 기기의 기존 조회를 유지한다.
3. 메인 상태 영역에 V/mA/W와 유효성 이유를 표시한다. 6초 넘게 갱신되지 않거나 연결이 끊기면 오래된 수치를 현재값처럼 남기지 않는다.
4. OTA는 초기 접힘 상태이며 슬롯/파일/전송/주의 내용을 함께 펼친다. 접기 동작 자체는 장치 명령을 보내지 않는다. 전체 화면 스크롤로 하단 조작에 접근할 수 있다. 태블릿은 상태/제어의 두 열을 유지한다.
5. 기존 시험과 빌드를 통과하고 실제 Android에서 화면/핵심 조작을 확인한다. 미실행 실기는 구분한다.

## 근거와 실행 계획

- 펌웨어 정본 [0x59 규격 §6](E:/workspace/projects/sullivan-1-5-fw-hw-test-link-pwr-bt-period/docs/참고/리모콘%20프로토콜/0x59%20프로토콜%20규격.md): 요청 `59 22 00 01`. 기존 접두 8바이트에 signed i32 µA, 상태 u8, 나이 u16 BE를 붙여 L=15. 상태 0 / 나이 2500ms 이하만 유효하다. 다른 PC에서는 이 절대 경로가 달라질 수 있다.
- [Python 배터리 표시](E:/workspace/projects/python-remote-app/new-remote-app/src/tdc_remote/ui/tdc_battery_panel.py), [파서](E:/workspace/projects/python-remote-app/new-remote-app/src/tdc_remote/protocol/tdc_packet_parse.py)와 대조했다. 다른 저장소의 경로는 현재 장비 기준이다.
- 표시 전류는 원시 전류의 부호를 반전해 방전 + / 충전 −로 한다. 전력은 `-mV × 원시 µA / 10^9` W. 전압/전류 취득 시점이 달라 순전력 추정치다. 전압 0은 미교정으로 전력 계산을 막는다.
- 배터리 응답에 현재 TX PMIC도 있으므로 지원 장치의 기존 현재 Tx 조회를 대체한다. 30초 상태/파라미터 조회 슬롯은 유지해 그 주기에는 배터리가 최대 4초 간격이 된다.
- 스크롤 바깥에 연결 안내 오버레이를 유지한다. 기존 카드와 컨트롤 ID를 보존하며, 태블릿의 고정 높이/서로 맞은편 기준 제약을 제거한다.

## 사용 방법

1. 연결 후 통합 상태 패널에 사용자·장치·펌웨어, 잔량·배터리 전압·평균 전류·추정 전력이 표시된다. 잔량도 다른 수치와 같은 크기다. 전류는 소수점 한 자리 mA, 전력은 mW다.
2. 아래에서 프로그램·볼륨·최대 출력과 FF 상태, 송신 전압/전압 제한/연결 타이밍/연결 방식/자극 설정/장치 동작을 한눈에 확인한다. 상태에는 가로 스크롤이나 숨겨진 페이지가 없다.
3. 기본 제어 / 소리·연결 / OTA 탭으로 조작 영역을 바꾼다. 긴 제어와 OTA 내용만 세로로 스크롤하며 상단 상태는 계속 남는다. 탭 선택 자체는 장치 설정을 변경하지 않는다.
4. 3.800 V × 30.0 mA = 114.0 mW다. 상태의 송신 전압은 이 계산에 사용하지 않는다. 무효 값은 —와 이유를 표시한다. 평상시 방전 문구와 샘플 나이는 표시하지 않는다.
5. 조회 주기는 보통 2초, 전체 상태 조회 차례에는 약 4초다. OTA/FF3 처리 중 양보하며 6초 넘게 갱신이 없으면 오래된 수치를 숨긴다.

이하 이전 단계의 화면/검증 기록은 당시 구현의 이력이며, 최종 화면은 문서 끝의 통합 상태 개편을 따른다.

## 시험 중 등록 초기화와 복원

최초 `connectedDebugAndroidTest` 실행에서 이 환경의 AGP 8.10.1 / UTP가 `uninstall_after_test: true`로 대상 앱까지 제거했다. 이로 인해 휴대전화의 등록 DB, 앱 환경설정과 과거 앱 로그가 초기화됐다. 당시 등록 DB를 백업하지 않아 원본 전체를 되돌리는 방식으로 복원할 수는 없었다.

Python 앱의 기존 데이터에서 동일한 박의규/왼쪽 사용자와 FFFF 장치를 확인해 기존 Room 형식으로 각각 1개씩 복원했다. 암호화/스키마 무결성과 재연결을 확인했으며, 개인 등록 데이터/키/백업은 Git에 추가하지 않았다. 은수님이 “이 대상만 있었음”으로 답해 이 1명/1대가 원래 등록 목록 전부임을 확인했다. 등록 정보 복원은 완료됐지만 **과거 앱 로그와 환경설정은 복원하지 못했다**.

재발 방지를 위해 설치된 AGP의 옵션 정의를 확인하고 [gradle.properties](../../../../source/gradle.properties)에 `android.injected.androidTest.leaveApksInstalledAfterRun=true`를 추가했다. 같은 Gradle 계측 시험을 다시 실행해 2개 통과 후 대상 앱이 설치된 채 남고 사용자 DB/장치 DB가 각각 1건 및 `integrity_check=ok`인 것을 확인했다. 앱을 다시 열어 동일한 REL4.6 연결과 배터리 갱신도 확인했다. 복원 데이터의 로컬 보호용 백업은 Git 밖의 임시 폴더에 보관했다.

## 후속 개정: 수치 단위와 제어 탭 (2026-10-23)

사용자가 전류 소수점 한 자리, 전력 mW, 잔량의 과도한 강조 제거와 전체 묶음 재설계를 요청했다. 이어 가로 스크롤·탭·스와이프도 고려하도록 요청했다.

- 함께 비교하는 배터리 정보는 가로 스크롤로 숨기지 않고 잔량/전압/평균 전류/소비 전력의 2×2 격자로 묶는다. 네 값은 모두 17sp다. 전류는 소수점 한 자리 mA, 전력도 소수점 한 자리 mW다. 전력은 반올림 전 원시 전류로 계산한다.
- 제어 영역은 ‘기본 제어 / 소리·연결 / 상태’ 탭으로 전환한다. 탭 변경은 화면 표시만 바꾸며 BLE 명령을 보내지 않는다. 화면 재생성 시 선택한 탭을 복원한다. 기본 제어에 소리 보상 요약을 함께 둔다.

- 제어 버튼 위 가로 스와이프는 적용하지 않았다. 탭을 항상 보여 추가 옵션을 발견하기 쉽고 버튼 터치와 구분되도록 했다. OTA는 별도 펼침/접기를 유지한다.
- 기존의 ‘장치 상세 상태 펼치기’는 상태 탭으로 대체했다. 바로 위 후속 기록의 펼침 버튼과 22sp 잔량 시안은 이 개정으로 대체된다.

## 앱바·기본 제어·OTA 정렬 보정

앱바의 사용자/외부기 목록 줄바꿈은 각 Fragment의 강제 개행 문자열에서 발생했다. 한 줄 문구로 바꾸고, 공통 앱바에서 뒤로가기 아이콘 뒤 84dp 문구 영역(시작 56dp)과 제목 영역(시작 inset 152dp)을 분리했다. 제목은 확보된 영역의 왼쪽에 정렬하며 긴 뒤로가기 문구는 한 줄 말줄임을 사용한다. 문구를 눌러도 기존 뒤로가기와 같은 동작을 하도록 연결했다. 제목 크기와 48dp 앱바 높이는 유지한다.

### PMIC 전용 조회 복원 및 REL4.5 직접 대조 (2026-10-28)

대상은 E:/workspace/projects/sullivan-1-5-fw-rel-4-5의 현재 작업 트리와 release_fw_ver-rel.4.4 기준이다. 이전 Develop 저장소의 과거 REL-4.5 태그를 새 REL4.5로 취급하면 안 된다.

- processorDirective.h:99~101의 disable_Tx_PowerControl은 #if 0 안에 있으므로 활성화된 기능 차단 매크로가 아니다. 이 매크로 때문에 0이라는 가설은 배제했다.
- REL4.4 대비 remoteControl_protocol.c, isd_interface_FPGA.c, isd_interface_init_FPGA.c는 차이가 없다. 관찰값 저장 누락은 새 REL4.5에서 조회를 제거한 결과가 아니라 REL4.4에서 이어진 구조다. REL4.5의 경계 로그 억제 변경도 저장값을 수정하지 않는다.
- Maximum(index16)은 새 REL4.5의 15개 항목 테이블에 없으므로 미지원이 맞다. 배터리 0x22 자체는 구형 8바이트 응답을 지원하지만 전류 확장이 없으며, 이번 앱 정책에서는 4.6 미만을 숨긴다.

소스 수준의 갱신 누락과 장치의 0 반환까지 확인했다. 현재 장치가 상한 유지/매핑/제어 미진입 중 어느 경로를 실행하는지는 BLE 값만으로 구분할 수 없다. 실제 하드웨어 전압이 0이라고 판단하지 않는다. 펌웨어 교차 리뷰에서는 성공한 read_txPowerLevel의 읽기값과 s_tdc_tx_pmic_pwr_level을 동일 시점에 비교하고, 성공한 실제 읽기·쓰기의 공통 경로에서 관찰값을 게시하도록 검토하면 된다. 추가 BLE 명령이나 PMIC 제어 정책 변경은 필요하지 않다. 펌웨어 소스 변경·플래시는 수행하지 않았다.
