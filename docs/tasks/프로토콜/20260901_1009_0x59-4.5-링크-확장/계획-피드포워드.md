# 계획

**TL;DR**: 5개 파일에 **6단계**. 순서의 핵심은 **읽기 큐를 먼저 만드는 것**이다 — 그것 없이는 인덱스 10개가 화면에 도달하지 않는다. 기존 인덱스 16 경로도 그 큐로 옮겨 경로를 하나로 만든다.

## 0. 확정한 결정

| 결정 | 확정 | 근거 |
|---|---|---|
| 게이트 | `is45LinkFeatureSupported()` 로 넓히고 `isMaxTxPowerSupported()` 는 위임으로 남긴다 | 규격이 «4.5 = 16 + 17~26» 을 한 덩어리로 정의 |
| 관측값 읽기 | FF 다이얼로그를 열 때만 | 폴링 금지 제약 |
| 버튼 | `FF` · Etc 4행 신설 | 3행이 찼다 |
| 자동 읽기 거절 | 토스트 없이 로그만 | 4.5 초기 빌드에서 10번 뜨는 것을 막는다 |

## 1. 단계

### 단계 1 — 읽기 큐 (`MainActivity.java`) ★ 먼저 한다

```java
private final ArrayDeque<Integer> mLinkReadQueue = new ArrayDeque<>();

/** 인덱스를 큐에 넣고, 지금 보낼 수 있으면 하나 보낸다. */
private void enqueueLinkRead(int index) { ... }

/** 응답을 처리한 자리에서 다음 하나를 보낸다. 비면 멈춘다. */
private void pumpLinkReadQueue() { ... }
```

- `handleRcLinkResponse()` 의 **개별 응답 분기 끝**에서 `pumpLinkReadQueue()` 호출
- 에러 응답에서도 호출한다 — 거절돼도 큐가 멈추면 안 된다
- **타임아웃**: 마지막 전송에서 `LINK_READ_QUEUE_TIMEOUT_MS`(3.5 s) 안에 응답이 없으면 큐를 비운다
- 기존 `requestMaxTxPowerRead()` 는 이 큐를 쓰도록 바꾼다 (경로 일원화)

### 단계 2 — 상수 (`PacketInfo.java`)

```java
RC_LINK_IDX_FF_ENABLE   = 17;  RC_LINK_IDX_FF_COOLDOWN = 18;  RC_LINK_IDX_FF_STEP = 19;
RC_LINK_IDX_FF_RATIO_0  = 20;  … RC_LINK_IDX_FF_RATIO_3 = 23;
RC_LINK_IDX_FF_RAISED   = 24;  RC_LINK_IDX_FF_APPLIED  = 25;  RC_LINK_IDX_FF_AVG_AMP = 26;
RC_LINK_IDX_MAX = 26;                      // 15 → 16 → 26
// 범위·기본값
FF_COOLDOWN_MIN/MAX/DEFAULT = 1/255/50
FF_STEP_MIN/MAX/DEFAULT     = 1/40/1
FF_RATIO_MIN/MAX            = 1/100
FF_RATIO_DEFAULT[]          = {5, 10, 15, 20}
FF_FALL_STEPS_PER_SEC       = 3;           // 백텔 300ms 에 1스텝 ≈ 3.3/s. 경고 비교용
```

`makeFfRiseStepsPerSec(step, cooldownMs)` 도 여기 둔다 — 화면과 경고가 같은 식을 써야 한다.

### 단계 3 — 뷰모델 (`StatusViewModel.java`)

인덱스 17~26 열 개의 LiveData. 기존 형태를 그대로 본뜬다.

### 단계 4 — 배선 (`MainActivity.java`)

| 무엇 | 어디 |
|---|---|
| 게이트 `case 17~26` | `isLinkParamSupported()` 의 `switch` |
| `is45LinkFeatureSupported()` | `isMaxTxPowerSupported()` 자리 |
| `applyLinkParam()` `case 17~26` | 값 반영 |
| 판별 완료 시 `enqueueLinkRead(16, 17…23)` | `advanceProbe()` 종료 자리 |
| 관측값 읽기 `requestFfObservation()` | FF 다이얼로그가 부른다 (24·25·26) |
| 쓰기 `sendFfParam(index, value)` | 범위 밖 거절 문맥 공유 |
| **자동 읽기 거절을 조용히** | 에러 분기에서 «큐가 도는 중» 이면 토스트 생략 |
| 경고 4건 | `makeLinkWarningText()` |
| 연결 해제 초기화 | 17~26 을 `LINK_VALUE_UNKNOWN` 으로 |

### 단계 5 — 화면 (`RemoteControlFragment.java`)

- `FF` 버튼 · `makeDialog_ffSettings()` — **`setCustomTitle`** 로 관측값을 제목에 얹는다
- 항목을 고르면 값 선택 다이얼로그 (enable 은 켬/끔 2택, 나머지는 범위 목록)
- `updateFfText()` — 4.5 미만이면 버튼 숨김

### 단계 6 — 레이아웃 (`fragment_remote_control.xml`)

Etc **4행 신설** : `FF` + 자리 맞춤 `Space` 3개 (4열 격자 유지)

상태 표시에는 넣지 않는다 — 이미 5열 × 5행이고, FF 는 다이얼로그에서 본다.

## 2. 손대지 않는 것

| 무엇 | 왜 |
|---|---|
| `RC_LINK_IDX_ALL_READ_MAX` (15) | 전체 읽기 포맷은 그대로다 |
| 인덱스 16 의 동작·UI | 이미 끝났다. 읽기 경로만 큐로 옮긴다 |
| 에러 `case 1`·`8`, 큐 밖의 `case 2` | 기존 문구 유지 |

## 3. 검증 계획 (단계 ⑧)

| 축 | 어떻게 |
|---|---|
| 빌드 | `assembleDebug` 통과 |
| 큐 | 인덱스 8개를 넣었을 때 **버려지는 것이 없는지** 로그로 확인 |
| 하위 호환 | 17~26 송신이 게이트 뒤에만 있는지 `grep` 전수 |
| 경고 식 | `19 * 1000 / 18 > 3` 을 규격 표와 대조 |
| 다이얼로그 | `setMessage` + 목록 조합이 없는지 전수 검사 (이번에 도구화한다) |
| 실기 | 불가 — 대기 항목으로 쌓는다 |

## 4. 실기 확인 항목

1. 연결 후 17~23 이 **하나도 빠짐없이** 읽히는가 (큐가 도는가)
2. 4.5 초기 빌드(16 만)에서 17~26 거절이 **토스트 없이** 흘러가는가
3. FF 를 켜고 제어 모드 1 로 두면 경고가 뜨는가
4. 스텝 4 · 쿨다운 50 으로 두면 «초당 상승» 경고가 뜨는가 (4 × 1000 / 50 = 80 > 3)
5. FF 다이얼로그를 열 때 24·25·26 이 갱신되는가
6. 4.3·4.4 에서 `FF` 버튼이 숨겨지고 기존 동작이 그대로인가
