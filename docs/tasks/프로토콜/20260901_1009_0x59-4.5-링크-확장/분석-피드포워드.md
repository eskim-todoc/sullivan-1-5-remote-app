# 분석

**TL;DR**: **가장 큰 걸림돌은 «읽기 10개를 연달아 보낼 수 없다» 는 것이다.** `sendPacket()` 이 전송 중이면 패킷을 **조용히 버린다**. 인덱스 16 하나일 때는 드러나지 않았던 제약이 10개가 되면서 전면에 나온다. 읽기 큐가 필요하다.

## 1. 결정적 제약 — 패킷을 연달아 못 보낸다

```java
// MainActivity.java:4228
public void sendPacket(byte[] packet)
{
    if (mStatus.transferState == Status.TRANSFER_STATE_BUSY)
    {
        Log.d(TAG, "패킷 전송 처리 중입니다. 잠시 후 다시 시도해주세요.");
        return;                       // ← 조용히 버린다
    }
    ...
}
```

`requestMaxTxPowerRead()` 처럼 `sendLinkParamRead(17)` … `sendLinkParamRead(26)` 을 늘어놓으면 **첫 하나만 나가고 아홉이 사라진다.** 로그만 남고 사용자에게는 «값이 안 들어온다» 로 보인다.

**선례가 있다.** 4.4 코인이 패킷 둘을 보내야 해서 `mPendingOneCoinValue` 로 «첫 응답이 온 자리에서 둘째를 보내는» 연쇄를 만들었다(`MainActivity.java:2407` · `:2528`). 지금 필요한 것은 그것의 **일반화된 큐**다.

| 무엇 | 어디 |
|---|---|
| 전송 잠금 | `MainActivity.java:4230` `transferState == BUSY` 면 버림 |
| 잠금 해제 | 응답 수신 경로 `:3118` · `:3320` · `:4154` |
| 연쇄 전송 선례 | `MainActivity.java:2407`(대기 값) · `:2528`(응답 자리에서 이어 보내기) |

**설계**: `ArrayDeque<Integer> mLinkReadQueue` 를 두고, 링크 응답을 처리한 자리에서 큐가 비어 있지 않으면 다음 인덱스를 보낸다. 인덱스 16 도 이 큐에 태워 경로를 하나로 만든다.

## 3. 화면 설계

설정 7개 + 관측 3개를 개별 버튼으로 두면 격자가 감당하지 못한다. **`FF` 버튼 하나 → FF 다이얼로그** 로 묶는다.

```
[FF] 버튼
  └ FF 다이얼로그 (setCustomTitle 로 «지금 상태» 를 얹는다)
      · 사용 : 켬 / 끔                (인덱스 17)
      · 쿨다운 : 50 ms                (18)
      · 스텝 : 1  (25 mV)             (19)
      · 비율 구간 0 : 5 %  (평균 0~63)   (20)
      · 비율 구간 1 : 10 % (64~127)      (21)
      · 비율 구간 2 : 15 % (128~191)     (22)
      · 비율 구간 3 : 20 % (192~255)     (23)
      항목을 고르면 기존 형태의 값 선택 다이얼로그가 열린다
```

**제목 자리에 관측값을 얹는다** — «평균 26 → 구간 0 적용 · 세움 12 / 올림 10 (2 합쳐짐)». 다이얼로그를 열 때 24·25·26 을 읽어 채운다(요구사항_2, 폴링 금지).

> [!IMPORTANT]
> **`setMessage` 와 목록을 같이 주면 목록이 사라진다.** 이 파일이 이미 두 번 겪었다
> (`RemoteControlFragment.java:2177` 주석 · 2026-09-01 Max PMIC 사고).
> **`setCustomTitle(makeDialogTitleView(...))` 를 쓴다.**

## 4. 경고 (요구사항_3·4)

`makeLinkWarningText()` 에 네 줄을 더한다. 규격이 심각도를 지정했다.

| 조건 | 심각도 | 문구 |
|---|---|---|
| `17==1 && 9==1` | 중간 | 피드포워드는 제어 모드 1 에서 동작하지 않습니다 |
| `17==1 && 13>=10` | 중간 | 백텔 미출력 구간 — 피드포워드가 동작하지 않습니다 |
| `17==1 && (6!=0 \|\| 8==1)` | 중간 | 강제 고정/무한 재시도 중 — 피드포워드가 올리지 않습니다 |
| `17==1 && 19*1000/18 > 3` | **높음** | 초당 상승이 하강(3.3/s)보다 큽니다 — 일정한 소리에서도 상한까지 올라갈 수 있습니다 |

마지막 것은 **곱셈 순서에 주의한다.** `19 * 1000 / 18` 로 계산해야 정수 나눗셈에서 잃지 않는다.

## 5. 위험

| # | 위험 | 완화 |
|---|---|---|
| 1 | **읽기 10개가 버려진다** | 큐 (§1) |
| 2 | 4.5 초기 빌드(인덱스 16 만)에서 17~26 이 거절되어 토스트 10번 | 자동 읽기 거절은 조용히 (요구사항_5). 큐가 비면 자연히 멈춘다 |
| 3 | 큐가 응답 유실로 멈춰 남은 인덱스를 영영 안 읽음 | 큐에 **타임아웃**을 둔다. 만료되면 큐를 비운다 — 값은 «모름» 으로 남고 화면이 «-» 를 보인다 |
| 4 | 연결 직후 읽기가 11개로 늘어 초기화가 느려짐 | 관측값 3개(24·25·26)는 **연결 시 안 읽는다.** FF 화면을 열 때만 읽는다 |
| 5 | `RC_LINK_IDX_MAX` 를 26 으로 올려 게이트 `default` 가 4.3·4.4 에서 통과 | 인덱스 16 때와 같다 — `case` 를 명시한다 |
| 6 | 실기 확인 불가 | 대기 항목으로 쌓는다 |

## 6. 열어 두는 결정

| 결정 | 기울기 |
|---|---|
| 게이트 이름 | `isMaxTxPowerSupported()` → **`is45LinkFeatureSupported()`** 로 넓히고 기존 이름은 그 위임으로 남긴다. «4.5 = 16 + 17~26» 이 한 덩어리라는 규격을 이름이 말하게 |
| 관측값 읽기 시점 | **FF 다이얼로그를 열 때만.** 폴링 금지 제약 |
| 버튼 이름 | **`FF`** — Etc 버튼이 짧은 영문 축약이다 |
