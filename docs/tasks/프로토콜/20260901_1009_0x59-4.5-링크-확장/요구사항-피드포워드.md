# 요구사항

**TL;DR**: 4.5 에 **인덱스 10개(17~26)** 가 더 붙었다. 백텔(300 ms)보다 먼저 반응해 «조용하다 큰 소리» 에 내부기가 죽는 것을 막는 **자극 레벨 피드포워드**다. 설정 7개 + 관측 3개이고 **전부 개별 읽기**다. 앱이 할 일의 핵심은 **«켜도 동작하지 않는 조건» 을 알리는 것**과 **설정 조합이 위험할 때 경고하는 것**이다.

## 1. 배경

은수님 지시 (2026-09-01): *"4.5에서 추가 기능이 업데이트 됐어. 확인하고 기능 업데이트좀 해줘"*

**버전 번호가 올라가지 않았다.** 4.5 가 아직 배포 전이라 같은 번호 안에 넣었다 — 은수님 *"동일한 REL4.5 라는 게 중요"*. 그래서 **4.5 = 인덱스 16 + 17~26** 이 한 덩어리다.

동작은 이렇다. CFX 가 자극 전략이 내보내는 채널의 자극 레벨 합을 **직전 프레임**과 비교해, 채널당 평균 구간별 비율 이상 커지면 플래그를 세운다. CM3 가 그것을 보고 PMIC 를 스텝만큼 **올린다**. 올리기만 하고 내리는 것은 백텔 `High` 판정에 맡긴다.

## 3. 요구사항

### 요구사항_1 — 4.5 하나로 다룬다

인덱스 16 과 17~26 을 **같은 게이트**로 묶는다. 은수님이 «동일한 REL4.5» 를 명시하셨고, 규격도 4.5 를 그렇게 정의한다. 별도 minor 를 만들지 않는다.

> [!NOTE]
> **«인덱스 16 만 있는 4.5»(커밋 `607ab9e`)를 배려하지 않는다.** 은수님 지시 (2026-09-01) —
> *"기존 4.5를 하위호환하는건 없어도 되는거 알지? 아까 했던 4.5가 끝난게 아니고 계속 연장선에 있는거야."*
> **4.5 는 «16 + 17~26» 하나뿐**이고 그 중간 상태는 없는 것으로 본다.
> 4.3·4.4 하위 호환은 별개이고 **그대로 지킨다.**

### 요구사항_2 — 개별 읽기로 가져온다

인덱스 16 과 같은 자리(**판별 완료 시점**)에서 17~26 을 이어 읽는다. 이미 만들어 둔 `requestMaxTxPowerRead()` 경로를 넓힌다.

관측값(24·25·26)은 **변하는 값**이라 한 번 읽고 끝나면 의미가 없다. 다만 상시 폴링은 부담이므로 **FF 화면을 열었을 때 갱신**한다.

### 요구사항_3 — «켜도 동작하지 않는 조건» 을 알린다

FF 를 켜도 아래에서는 올라가지 않는다. 사용자가 «켰는데 왜 안 되지» 로 헤매지 않게 **그 자리에서** 알린다.

| 조건 | 왜 |
|---|---|
| 인덱스 9(제어 모드) = 1 | 그 모드는 상한 도달을 끊김 판정에 쓴다. 미리 올리면 판정이 앞당겨진다 |
| 매핑 진입 중 | Normal 전용이다 |
| 인덱스 13(패킷 수) ≥ 10 | 백텔이 안 나가 하강 경로가 없다. 올리기만 하게 된다 |
| 인덱스 6 ≠ 0 (강제 고정) 또는 8 = 1 (무한 재시도) | 고정·동결이 우선이다 |

### 요구사항_4 — 위험한 조합을 경고한다

**초당 상승 = 인덱스 19 × (1000 / 인덱스 18)** 스텝이다. 하강은 **3.3 스텝/s** 뿐이라(백텔 300 ms 에 1스텝), 상승이 그보다 크면 **일정한 말소리에서도 상한까지 올라간다.**

펌웨어는 막지 않는다(시험 수단). **앱이 경고한다** — 규격이 심각도 «높음» 으로 지정했다.

### 요구사항_5 — 읽기 큐가 거절에 멈추지 않는다

~~«없는 인덱스의 거절을 조용히 흘린다»~~ — **철회했다.** 그 요구는 «인덱스 16 만 있는 4.5» 를
배려하려던 것인데, 은수님이 그럴 필요 없다고 하셨다(§3 머리의 NOTE).

대신 남는 것은 **견고성 하나**다. 읽기 큐는 응답이 오든 거절이 오든 **다음 인덱스로 넘어가야 한다.**
거절 하나에 큐가 멈추면 뒤의 인덱스가 영영 안 읽힌다. 토스트 동작은 **기존 그대로 둔다.**

### 요구사항_6 — 관측값을 읽을 수 있게 한다

| 값 | 어떻게 보여 주나 |
|---|---|
| 26 현재 평균 amplitude | **지금 어느 구간(20~23)이 적용되는지**를 함께 보여 준다. 규격이 «구간 판정과 같은 값» 이라고 못 박았다 |
| 24 − 25 | **합쳐진(놓친) 요청** 수다. 둘 다 하위 8비트라 **차분을 mod 256** 으로 본다 |

### 요구사항_7 — 화면

설정 7개를 각각 버튼으로 두면 Etc 격자가 감당하지 못한다(3행이 이미 찼다). **`FF` 버튼 하나 → FF 전용 다이얼로그**로 묶고, 그 안에서 항목을 골라 기존 형태의 값 선택 다이얼로그를 연다.

4.5 미만이면 버튼을 숨긴다.

## 4. 제약

| 제약 | 내용 |
|---|---|
| 규격 준수 | 인덱스·범위·기본값은 펌웨어 문서가 유일한 근거다 |
| 하위 호환 | 4.3·4.4 에서 기존 동작이 하나도 바뀌면 안 된다. **인덱스 16 작업의 동작도 그대로** 유지한다 |
| 전체 읽기 | 여전히 앞 15개다. `RC_LINK_IDX_ALL_READ_MAX` 를 건드리지 않는다 |
| 폴링 금지 | 관측값을 주기적으로 읽지 않는다. 링크 트래픽을 늘리면 백텔에 영향이 갈 수 있다 |
| 미검증 | 실기 확인 전까지 «확인됨» 으로 적지 않는다 |

## 5. 범위 밖

| 항목 | 왜 |
|---|---|
| CFX·CM3 의 피드포워드 동작 | 펌웨어가 구현했다. 앱은 값만 정하고 관측한다 |
| 관측값 그래프·기록 | 지시에 없다 |
| 인덱스 16 작업 재설계 | 이미 끝났다. 게이트만 공유한다 |
