# 요구사항 검증

**TL;DR**: 요구사항 8건을 펌웨어 문서 세 곳과 줄 단위로 대조했다. 전부 근거가 있고 추측으로 넣은 것은 없다. 다만 의존성 문서 안에서 백텔 모드의 코인 잠금 규칙이 **서로 어긋나** 있어, 어느 쪽을 따를지는 분석에서 판정한다.

## 축_1 — 지침 준수

| 항목 | 판정 |
|---|---|
| 한글 라벨 | 통과 (`요구사항_1`~`요구사항_8`) |
| frontmatter + TL;DR | 통과 (TL;DR 118자) |
| 근거는 정본 문서로 | 통과 — 펌웨어 `docs/참고/리모콘 프로토콜/` 세 문서 |
| 추측 금지 (헌법 §7) | 통과 — 모든 항목에 문서 줄 근거 |

## 축_2 — 논리적 정합성

| 검사 | 판정 |
|---|---|
| 요구사항_1 ↔ 요구사항_5 | 정합 — 4.3 이하는 기존 잠금, 4.4 는 새 규칙. 버전으로 갈린다 |
| 요구사항_7 ↔ 요구사항_2 | 정합 — 읽을 때는 두 인덱스를 함께 보고, 쓸 때는 인덱스 7 하나만 쓴다 |
| 요구사항_4 ↔ 요구사항_2 | 정합 — 무한이 목록 맨 앞이고 휘발이라는 안내가 붙는다 |
| 요구사항_6 ↔ 요구사항_1 | **주의** — 상승 스텝 동반 효과는 4.4 부터다. 4.3 에 붙었을 때 이 경고가 뜨면 틀린 안내가 된다. **버전으로 가려야 한다** |
| 요구사항_8 ↔ 요구사항_5 | 정합 — 무한이면 `∞`, 개수가 무시되는 모드면 그 사실을 표시 |

## 발견 — 펌웨어 문서 안의 불일치

`설정 의존성과 앱 UI 규칙.md` 가 백텔 수신 기준 모드의 코인 잠금을 **세 곳에서 다르게** 말한다.

| 위치 | 내용 | 판정 |
|---|---|---|
| `:70` §3 매트릭스 | *"인덱스 7 의 **개수 구간(`0`·`1~100`)만** … `255`(무한)는 이 모드에서도 유효하다 — 잠글 때 개수만 잠근다"* | 4.4 반영됨 |
| `:178` §6.1 표 | *"재시도 코인 (7) — **개수 구간만**"* | 4.4 반영됨 |
| §6.1 의사코드 | `enable(oneCoin, !linkFrozen && !isBacktelMode);` — **코인을 통째로 잠근다** | **4.4 이전 그대로** |

> [!WARNING]
> **의사코드가 갱신에서 빠진 것으로 보인다.** 산문 두 곳이 «개수만» 이라고 명시하고 그 이유(무한은 코인 소모 분기 밖)까지 적혀 있는데, 의사코드만 옛 규칙이다.
>
> **분석에서 «개수만 잠근다» 를 채택한다.** 근거가 둘이고 이유가 적혀 있는 쪽이다. 은수님께 보고해 펌웨어 문서를 고치도록 한다.

## 결론

요구사항을 그대로 넘기되 **요구사항_6(상승 스텝 경고)은 4.4 이상에서만 뜨도록** 분석에서 조건을 붙인다.
