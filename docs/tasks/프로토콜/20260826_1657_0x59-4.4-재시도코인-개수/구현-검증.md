# 구현 검증

**TL;DR**: 빌드가 통과했고 기계 대조 25항목이 전부 맞았다. 4.3 이하 경로는 하나도 지우지 않았음을 따로 확인했다. 남은 것은 실기뿐이며, 특히 백텔 모드에서 무한이 유효한지는 문서 불일치를 판정으로 넘긴 부분이라 반드시 확인해야 한다.

## 축_1 — 지침 준수

| 항목 | 판정 |
|---|---|
| 기존 파일의 명명 규칙 유지 | 통과 — `RC_`·`COIN_` 접두어. 새 모듈이 아니라 `tdc_` 대상이 아니다 |
| 주석에 «왜» 를 남긴다 | 통과 — 인덱스 7 을 먼저 보는 이유, 4.3 경로를 남기는 이유 등 |
| 회귀 fix 시 호출 경로 전수 확인 (헌법 §7) | 통과 — `grep` 으로 코인 참조 전부 훑고 4곳을 고쳤다 |

## 축_2 — 계획 대조

| 단계 | 결과 |
|---|---|
| 단계_1 상수 | `RC_PROTOCOL_MINOR_COIN_COUNT` · `COIN_COUNT_*` 4개 · `COIN_STEP_UP_WARN_LEVEL` |
| 단계_2 판정 | `isCoinCountSupported` · `isCoinInfinite` · `isCoinCountEffective` + `isLinkSettingUsable(7)` 분기 |
| 단계_3 전송·경고 | `sendCoinCount` · 무한 경고를 새 판정으로 · 상승 스텝 동반 효과 경고 |
| 단계_4 화면 | 개수 다이얼로그 · 견디는 시간 · 안내 · `updateCoinText` · `markAlert` |

**계획에 없던 것을 하나 추가했다** — `isCoinRetryActive()`. 상승 스텝 경고를 «코인이 실제로 쓰이는 상태일 때만» 띄우려면 필요했다. 계획의 조건을 함수로 뽑은 것이라 범위를 넘지 않는다.

## 축_3 — 기계 대조

빌드 `assembleDebug` **통과**. 아래는 스크립트 대조 결과다.

| 묶음 | 항목 수 | 결과 |
|---|---|---|
| 신규 구현 | 18 | 전부 통과 |
| 4.3 이하 경로 보존 | 5 | 전부 통과 |
| 다이얼로그 배열 무결성 | 2 | 전부 통과 |

보존을 확인한 것: `sendCoinMode` · `sendPendingOneCoinPacket` · `makeDialog_coinModeSelect` · `getCurrentCoinModeIndex` · `COIN_MODE_*`.

## 구현 지시 이행

| 지시 | 이행 |
|---|---|
| _1 배열을 한 반복으로 함께 | `values[at]`·`items[at]` 를 같은 `for` 에서 채운다. 길이도 `2 + (MAX - MIN + 1)` 로 한 번에 산출 |
| _2 주기를 모르면 시간 생략 | `makeCoinHoldTimeText()` 가 `LINK_VALUE_UNKNOWN` 과 `<= 0` 에서 빈 문자열 |
| _3 4.3 경로 유지 | 위 대조표 |

## 고친 결함

| 결함 | 내용 |
|---|---|
| **문자열 리터럴이 개행으로 깨짐** | 셸 heredoc 으로 `\n` 을 넣으려다 실제 개행이 들어가 컴파일이 깨졌다. **JSON 을 거치며 `\n` 이 접히는 함정**이고 이 저장소에서 두 번째다. 셸을 거치지 않는 편집 도구로 고치고 `System.lineSeparator()` 를 쓰도록 바꿨다 |
| **접근자 이름 오인** | `getValueTxPowerStepUp()` 로 썼으나 실제 이름은 `getValueTxStepUp()` (`StatusViewModel.java:277`) |
| **미상 판정이 4.4 에서 틀림** | 인덱스 8 을 아직 못 읽었을 때 `Coin -` 로 남았다. 4.4 는 인덱스 7 하나로 상태가 다 드러나므로 그 조건에서 빼도록 고쳤다 |

## 은수님께 보고할 것

**펌웨어 문서 `설정 의존성과 앱 UI 규칙.md` 의 §6.1 의사코드가 4.4 갱신에서 빠졌다.**
