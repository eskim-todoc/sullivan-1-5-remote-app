## 2026-10-01 FF3 사용성 개편

사용자의 우선 목적은 작은 변화도 빠르게 감지하는 조건 조정이다. 첫 화면에 감지할 증가 폭, 1ms 입력 확인 길이, 이름으로 선택하는 입력 방식을 함께 배치했다. 감지 조건, 소리 크기별 보상량, 다시 감지할 조건/요청 처리 시간을 목적 선택으로 나눴다. 보상 한도는 감지 민감도가 아니며 소리 구간 상승과 실행 조건도 필요하다는 관계를 설명한다. 모든 설정의 쉬운 이름·조정 방향·단위·기술명을 연결하고 `?` 도움말에 상세 설명을 넣었다.

입력값은 목적 전환 때 보존한다. 미사용 구간은 기본으로 접고 모든69개 값을 계속 보존한다. 필터와 전원 여유 확인은 숫자 대신 선택지를 제공하고 AR 상승 시간은 AR 선택 때만 수정된다. 첫 구간의 고정0 두 값과 보정표1은 읽기 전용이다. 자동 추천값/프리셋/미사용 값 삭제는 추가하지 않았다.

설정 창 안에 변경 전후 확인 → 저장/검사/전체 되읽기 → 별도 FF3 켜기를 연결했다. 태블릿에서는 주요 조작과 취소를 아래 고정 영역에 나란히 둔다. 화면 입력이 바뀐 상태로 닫거나 다시 읽으면 버릴지 확인하고, 통신 중 닫기는 장치 요청을 취소하지 않는다고 알린다. 합계 오류는 관련 목적과 보상 한도로 이동한다. 오류 수정 시 예전 오류 문구를 지운다. 동작 확인은 쉬운 요약을 먼저, 기술 진단은 접힌 영역에 제공한다.

`Ff3Ui`는 이름·도움말·표시 단위·변경 목록을 소유한다. `Ff3Config` 검증 계약과 `Ff3Session`의 요청/응답/저장/ACK 경계는 유지하고 안내 문구를 바꿨다. 메인 버튼과 상단도 `보상 방식/소리 보상 설정/보상 동작 확인`, `보상 한도/입력 처리부 확인/보상 기록`으로 표시한다.

## 2026-10-01 읽는 방식 선택 버튼 수정과 실증 (16:29~16:34)

사용자는 `소리 변화 읽는 방식`이 MA2로 고정되고 버튼이 활성화되지 않는다고 보고했다. 실제 화면은 모드OFF/status0x19로 장치 편집 전이었다. 조회 화면에서 숫자와 선택 버튼을 모두 비활성화한 앱 UI가 원인이며, 모드를OFF로 바꿔도 BEGIN 없이 편집 가능한 것은 아니다. 펌웨어의 MA2 고정 제약으로 판정하지 않는다.

[Ff3Dialog](../../../../source/app/src/main/java/todoc/cochlear/remoteapp/ff/Ff3Dialog.java)의 선택 버튼에 `바꾸기 ▾`를 표시하고 조회 중에도 누를 수 있게 했다. 누르면 보상OFF/편집 시작을 먼저 설명하고, 사용자가 확인한 뒤 BEGIN/전체 조회가 끝나면 요청한 선택 창을 연다. 이미 장치 편집이 남아 있으면 BEGIN으로 초기화하지 않고 이어서 선택한다. 선택만으로 장치 값을 저장하지 않으며 기존 변경 검토/VALIDATE/SAVE_APPLY/되읽기 순서를 유지한다. 처리 중·미지원·값 미조회·재연결 필요에서는 차단한다. 같은 선택 UI를 사용하는 전원 여유 확인 사용(index58)에도 적용하되 index58의 실제 변경 저장은 이번 시험 범위가 아니다.

## 2026-10-01 dB와 리니어 배수 동시 표시 (16:45~16:48)

사용자는 dB만 보면 입력 크기가 몇 배인지 이해하기 어렵다고 요청했다. dB로 입력·저장하는 계약은 유지하고 화면 해석을 보완했다. CFX `signalProcessing/agc.c`의 `s_tdc_audio_ff_ratio_q10`과 `audio_ff_above_db`는 진폭비를 사용하므로 설명용 배수는 `10^(dB/20)`이다. +6dB 약2배/+12dB 약4배이며 -6dB는 약0.5배다. 전력비의 `10^(dB/10)`이나 지각 음량 배수로 표시하지 않는다. 음압식의 외부 근거는 [OSHA 기술 매뉴얼](https://www.osha.gov/otm/section-3-health-hazards/chapter-5), 실제 적용 근거는 제공 펌웨어 코드다.

[Ff3Ui](../../../../source/app/src/main/java/todoc/cochlear/remoteapp/ff/Ff3Ui.java)는 증가43/44/53, 감소46, 안정52, 하강 경계56의 방향과 비교 기준을 구분하고 소수 둘째 자리 근사값을 표시한다. dBSPL 구간 경계는 직전 유효 경계와의 차이를 음압비로 표시하며 첫 하단0·미사용0·첫 경계·잘못된 경계를 별도로 설명한다. 원시 마이크값은 보정표를 따르므로 dBSPL 차이의 음압비를 ADC 원시값 비율로 단정하지 않는다. [Ff3Dialog](../../../../source/app/src/main/java/todoc/cochlear/remoteapp/ff/Ff3Dialog.java)의 입력 아래 설명은 매 입력에 갱신하고 빈값/범위 밖 입력에는 마지막 배수를 남기지 않는다. 현재 입력 요약과 저장 전후 비교에도 두 단위를 함께 표시한다.

- [빌드·시험](dB-배수-20261001/빌드-시험.log): 26개 통과(기존23개+진폭식/방향·locale/경계특수값3개). 독립 기준20dB=10배,-20dB=0.1배,6dB≈1.995262315,48dB≈251.1886432와 감소/안정/직전 경계 기준을 검사했다.
- 수정 APK를 SM-X205N/R8YW80731HH에 설치했다. SHA256 `CD4B039EB7E09FDFBDC91755D1D4424AACADB14C2CC68071BCB25E462E1055A6`. 최종 코드에서 빌드·시험을 재실행했다. 처음에는 안내 한 줄 추가로 배수 설명이 화면 아래에 잘려서, 위 안내를 도움말로 옮기고 입력 바로 아래 배수를 첫 화면에 보이게 했다.
