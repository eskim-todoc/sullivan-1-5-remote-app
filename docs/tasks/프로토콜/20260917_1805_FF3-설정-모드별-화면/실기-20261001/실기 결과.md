# FF3 태블릿 실기 결과

## 1. 판정

**현재 장치에서 FF3 조회·편집·폐기·저장·별도 활성화·재접속 편집 복구가 된다.** G만11→12로 저장하고 FF3를 켠 뒤 FF 가산 성공 기록과 쓰기 카운터 증가를 확인했다. 종료 전에 최초69개 설정과 모드3/G11을 복원했고 BLE 재접속에서도 일치했다. 연속 전체 조회는 기존 앱에서 두 차례 시간 초과가 발생했고, FF3 전송 간격을50ms로 조정한 앱에서는 연속3회와 후속 제어가 성공했다. 이 표본으로 모든 BLE 유실이 해결됐다고 단정하지 않는다.

사용자가 사람이 착용하지 않고 테스트 내부기와 연결된 상태임을 확인한 뒤 쓰기 시험을 진행했다. 장치 전원 재부팅, 통제 음압과 PMIC rail/자극 계측은 미수행이다. 제어 절차와 항목별 뜻은 [사용과 제어 방법](../../../../FF3%20사용과%20제어%20방법.md)에 작성했다.

FF 쓰기 카운터 증가와 결과2는 펌웨어가 PMIC 가산 쓰기를 수행했다고 보고하는 근거다. 외부 전압 측정이나 내부기 보호 효과의 확인은 아니다. 진단 페이지들은 순차 조회이므로 한 화면의 모든 필드가 같은 순간이라고 가정하지 않는다. 장부 무효화1502는 과거 누적수이고 현재 장부는1이었다.

수정 앱의 두 진단 조회(14:47:16~17,14:47:36~37)도 성공했고 FF 쓰기685→707, event635→656을 확인했다. TTL 만료 누적은1이었으며 FF 가산은 계속 보고됐다. [원시 진단 응답](05-수정후-진단.log). 수치와 시간별 기록의 해석은 [펌웨어 교차 리뷰 요청](../펌웨어%20교차%20리뷰%20요청.md)에 질문으로 남겼다.

### 쓰기 시험과 최종 복원

14:55:15.553에 OFF,14:55:16.248에 BEGIN을 보내 각 에코를 받았다. G10 입력에서 `증가량 합계는 0보다 크고 G 이하이어야 합니다. (합계 11)`로 앱이 차단했다. 이 G10은 장치에 보내지 않았다.14:56:23.450에 ABORT를 보내고 실행값을 읽어 OFF/편집 종료/원래 설정 보존을 확인했다.

두 번째 편집에서는14:57:41.951에 index50=12만 변경하고 VALIDATE/SAVE_APPLY 응답을 받았다. 전체69개 되읽기에서 G만12로 바뀌었고 OFF/CFX ACK/파일 확인0이었다.14:58:46.969에 별도로 모드3을 선택했다. 두 진단의 FF 쓰기는1054→1062, event9→15, 스냅샷1295744→1310294, 결과2/실제Δ2/age1ms/장부1이었다. G12는 단일값의 가역 저장 시험값이며 권장 설정이 아니다.

복원을 위한 OFF/BEGIN 후 앱을 재실행해 이전 편집이 남음을 확인했다. `이전 편집 계속`으로 재개하고15:01:37.249에 index50=11을 보냈다. VALIDATE/SAVE_APPLY와 전체 재조회 후69개 최초값 일치, OFF, 파일 확인0을 확인하고 별도로 모드3을 복원했다.15:02:46 이후 최종 BLE 재접속에서도 [종료 설정](종료-설정.json)은 [최초 설정](초기-설정.json)의69개와 모두 같았다. mode3/status0x19/schema3/G11, 편집 없음과 파일 확인0을 확인했다. 프로그램/음량/구간 표/필터는 바꾸지 않았다.

| 단계 | 파일 generation | CRC | 파일 확인 |
|---|---:|---|---|
| 최초 | 2 | 0xd7b3c00a | 0, 성공 |
| G12 저장, OFF | 4 | 0x02a79ae9 | 0, 성공 |
| G12, 별도 모드3 | 5 | 0x4b0ef1a5 | 0, 성공 |
| G11 복원 저장, OFF | 7 | 0xf26ca0cb | 0, 성공 |
| G11/모드3 복원 후 재접속 | 8 | 0xd4dc51f6 | 0, 성공 |

파일 generation/CRC는 실제 저장과 모드 변경으로 달라졌다. **설정과 모드는 복원됐지만 파일 메타데이터가 최초값으로 돌아간 것은 아니다.** 최종 확인은2026-10-01T15:03:29+09:00이다. 쓰기 시험 구간에서 F0/FF3 시간 초과는 관찰하지 않았다. 뒤의 로그들은 동일 PID의 앞선 기록도 포함하므로 시험 시각별로 구분한다.

## 4. 발견한 문제와 변경

두 실패 모두 특정 설정 인덱스의 정상 응답들이 이어진 뒤 서로 다른 인덱스에서 멈췄다. 각 실패 요청에 대한 BLE 수신 로그가 없으며 F0 거부도 없었다. 앱의 기존 전송 지연은1ms였다. Android GATT/장치 indication 처리 여유 부족을 가설로 세웠으며, 무선 유실이나 펌웨어 응답 처리 문제는 배제하지 않았다.

`MainActivity.sendPacket`에서 FF3가 보내는 요청만50ms 지연하도록 변경했다. 기존 일반 명령 지연은 유지한다. GATT 쓰기 완료 실패 status도 로그로 남긴다. 쓰기 자동 재전송, 기본값 덮어쓰기, PMIC 초기화는 추가하지 않았다.50ms는 이번 실기의 경험적 완화이며 펌웨어가 보장한 최소 간격이 아니다.

수정 전후 모두 `:app:testDebugUnitTest :app:assembleDebug` 통과, FF3 18개+기존1개 시험 통과. [수정 전 빌드](빌드-수정전.log), [수정 후 빌드](빌드-수정후.log). 전체 lint는 이번에 다시 실행하지 않았으며 기존 작업의45개 오류는 별도 남아 있다.

`git diff --check` 통과. 저장소 전체 Markdown 링크 검사는 기존 20260826 작업의 외부 상대경로3개가 깨져 실패했다. 변경 문서5개의 내부 링크77개는 별도 검사에서 실패0이었다. 전체 문서 통과로 표시하지 않는다.50ms 전체 조회3회를 각각 나눠69개값을 최초값과 대조해 세 번 모두 불일치0이었다. 이 초기 읽기 단계에서는 설정 쓰기0회였으며 후속 제어 시험과 구분한다.
