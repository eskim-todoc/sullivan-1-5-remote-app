# 요구사항 — 글래스모피즘 테마

**TL;DR**: 리모컨 화면 **하나만** 다크 글래스로 시범 전환한다. Android 12+ 는 실블러, 6~11 은 반투명 근사로 **이원화**한다. 의료기기 리모컨이므로 **가독성이 미관보다 앞선다** — 상태값·경고는 WCAG AA 를 하한으로 못박는다.

## 인터뷰 기록

은수님 지시: *"ui-glass 에이전트와 함께 지금 앱 디자인을 글래스모피즘 테마로 변경해봐."*

지시가 «앱 디자인» 이라 범위·밝기·구형기기·선행작업 넷이 모호했다. 답에 따라 결과물이 크게 갈리므로 착수 전에 여쭈었고, **넷 모두 권장안을 택하셨다.**

| | 질문 | 답 | 이 답이 바꾸는 것 |
|---|---|---|---|
| 질문_1 | 적용 범위 — 화면 18개 중 어디까지 | **리모컨 화면으로 시범** | 나머지 17개 화면은 손대지 않는다. 한동안 두 디자인이 섞여 보이는 것을 감수한다 |
| 질문_2 | 유리를 어두운 바탕에 올릴까 밝은 바탕에 올릴까 | **다크 글래스** | ~~본문 테마가 Light 에서 Dark 로 뒤집힌다~~ → **정정**: 이 화면은 이미 어둡다(아래 §정정_1). 뒤집는 것이 아니라 **어두운 단색을 유리로 바꾸는** 일이다 |
| 질문_3 | 구형 기기(API 23~30) 처리 | **이원화** | 두 벌을 유지한다. API 31+ 는 `RenderEffect` 실블러, 그 아래는 반투명·그라데이션 근사 |
| 질문_4 | 미커밋 4.5 작업 | **먼저 커밋하고 시작** | 완료 — `b55a663`. 테마 diff 가 4.5 와 섞이지 않는다 |

## 요구사항

### 요구사항_1 — 리모컨 화면만 바꾼다

`res/layout/fragment_remote_control.xml` 과 그 화면이 쓰는 drawable 만 대상이다. 공용 파일(`styles.xml`·`colors.xml`)은 **추가만** 하고 기존 스타일의 값을 바꾸지 않는다 — 바꾸면 나머지 17개 화면이 딸려 변한다.

### 요구사항_2 — 다크 글래스

어두운 배경 위 반투명 표면. 툴바·상태바·하단 네비와 이어지게 한다.

> [!IMPORTANT]
> **정정_1 — 이 화면은 이미 어둡다.**
> 착수 시 나는 앱 테마 부모가 `Theme.MaterialComponents.Light.NoActionBar` 인 것만 보고 «본문이 밝다» 고 적었다. 틀렸다.
> `fragment_remote_control.xml:8` 이 루트에 `android:background="@color/white_10"` 을 걸고 있고 `white_10` 은 **`#FF191919`** 다.
> 이 저장소의 `white_*`·`black_*` 램프는 **이름이 뒤집혀 있다** — `white_10` 이 거의 검정이다. **색 이름을 밝기로 읽으면 안 된다.**
> 따라서 이번 작업은 «밝은 화면을 어둡게» 가 아니라 **«이미 어두운 단색 화면을 유리로»** 다. 배경 레이어를 새로 깔 필요가 있는지부터 다시 판단해야 한다.

### 요구사항_3 — 기기 이원화

| 구간 | 방식 |
|---|---|
| API 31+ (Android 12~) | `RenderEffect.createBlurEffect` 실시간 블러 |
| API 23~30 (Android 6~11) | 반투명 + 그라데이션 + 하이라이트 테두리 근사 |

**두 구간 모두에서 요구사항_4 를 만족해야 한다.** 근사 쪽이 대비를 못 지키면 근사 쪽 수치를 바꾼다.

### 요구사항_4 — 가독성이 미관보다 앞선다 (양보 불가)

이 앱은 인공와우 착용자가 쓰는 **의료기기 리모컨**이다. 화면에 배터리·전극 상태·펌웨어 버전·경고가 뜬다.

- 상태값·경고 텍스트는 **WCAG AA 이상**(본문 4.5:1, 큰 글씨 3:1)

**유리 두께의 정량 예산 (실측 계산).** 배경 `#191919` 위에 흰빛을 얹어 유리 표면을 만들 때, 현행 분류색을 유지한다는 전제의 대비다.

| 흰빛 | 표면색 | 노랑 | 시안 | 핑크 | **경고 빨강** | 본문 |
|---|---|---|---|---|---|---|
| 0% (현행) | `#191919` | 12.46 | 9.57 | 5.75 | **5.51** | 13.96 |
| 6% | `#272727` | 10.59 | — | — | **4.68** | 11.86 |
| **7%** | `#292929` | — | — | — | **4.50 (한계)** | — |
| 10% | `#303030` | 9.35 | — | — | **4.14** 미달 | 10.48 |
| 14% | `#393939` | 8.18 | 6.28 | 3.78 | **3.62** 미달 | 9.17 |
| 24% | `#505050` | 5.71 | — | — | **2.53** 미달 | 6.40 |

**경고 빨강 `#FF5252` 가 병목이다.** 색을 그대로 두면 유리의 흰빛 상한이 **7%** 이고, 그건 매우 얇은 유리다. 두껍게 가려면 경고·핑크를 밝혀야 한다 — 14% 표면 기준 후보: `#FF8A80` 5.06:1 · `#EF9A9A` 5.37:1 · `#FF7B72` 4.58:1.

이 갈림길의 선택은 **계획서에서 결정**한다.
- 배경 그라데이션의 **가장 밝은 지점과 가장 어두운 지점 양쪽**에서 대비를 계산한다 — 한 지점만 재면 반대편에서 깨진다
- **유리 위에 유리를 겹치지 않는다** (겹침 깊이 1). 겹치면 최종 대비를 예측할 수 없다
- 착용자에 고령자·저시력자가 있음을 전제한다

### 요구사항_4-1 — 분류 색은 두 곳을 함께 고친다

상태 격자의 분류 색이 **레이아웃 10곳**과 **Java 상수 4개**(`RemoteControlFragment.java:3381~3384`)에 같은 값으로 중복돼 있다. 코드 주석이 *"레이아웃과 값이 같아야 하므로 한곳에 모아 둔다"* 라고 밝힌다. 한쪽만 고치면 **경고를 껐을 때 되돌아가는 색이 어긋난다**(`markAlert()` 가 원래 색으로 복원하는 구조).

### 요구사항_5 — 기능·배선을 건드리지 않는다

DataBinding 참조, 뷰 id, `ConstraintSet` 재배선(태블릿 2단), 4.5 에서 새로 붙은 위젯(`ota_ff_button`·`ota_max_pmic_*`)이 그대로 동작해야 한다. **이번 작업은 겉모습만 바꾼다.**

### 요구사항_6 — 태블릿 2단을 깨지 않는다

`sw600dp`·`sw720dp`·`sw900dp` 대응과 `ConstraintSet` 런타임 재배선이 이미 있다. 폰 세로와 태블릿 가로 양쪽에서 확인한다.

### 요구사항_7 — 되돌릴 수 있게 한다

시범이므로 은수님이 보시고 무를 수 있어야 한다. 테마 작업은 **별도 커밋 한 덩어리**로 두어 `revert` 하나로 되돌아가게 한다.

## 수용 기준

| | 기준 | 확인 방법 |
|---|---|---|
| 수용_1 | 빌드 통과 | `assembleDebug` |
| 수용_2 | 리모컨 화면 외 17개 화면의 모양이 그대로 | 변경 파일 목록에 다른 화면이 없음 + 실기 |
| 수용_3 | 상태값·경고가 배경 양단에서 AA 이상 | 대비비 **계산표** (눈대중 금지) |
| 수용_4 | API 31+ 와 30 이하 양쪽에서 화면이 성립 | 실기 2대 (은수님) |
| 수용_5 | 4.5 위젯·태블릿 2단이 그대로 동작 | 실기 (은수님) |
| 수용_6 | 테마 변경이 단일 커밋 | `git log` |

## 범위 밖

- 나머지 17개 화면 (질문_1 에서 제외)
- 다이얼로그 26개의 글래스화 — 리모컨 화면이 여는 것만 필요 시 검토
- 라이브러리 추가 — 의존성 없이 가는 안을 1순위로 하되, 불가 판정 시 근거와 함께 다시 여쭙는다
- `build.gradle` 의 `compileSdk` 이중 선언 (별건, 이력에 기록만)
