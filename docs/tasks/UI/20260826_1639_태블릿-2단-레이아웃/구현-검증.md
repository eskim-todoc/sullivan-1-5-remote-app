# 구현 검증

**TL;DR**: 빌드가 통과했고 기계 대조 22항목이 맞았다. 치수 112곳을 리소스로 뺐고 폰 화면은 값이 같아 불변이다. `ConstraintSet` 함정 세 가지를 모두 피했음을 코드로 확인했으나, 오버레이 제약 보존은 실기로만 확인된다.

## 정정

**«바인딩 참조 108곳»은 프래그먼트만의 수였다.** `MainActivity` 12곳을 더하면 **120곳**이다. 분석·계획 문서의 수치를 고쳤다. 무손상이라는 결론은 그대로다 — 편집 전후 두 파일 모두 수가 같다.

## 순서 확인

`applyScreenOrientation()`(`MainActivity.java:455`)이 `RemoteControlFragment` 생성(`:568`)보다 앞이라, 프래그먼트가 만들어질 때 `sIsTabletAtLaunch` 는 이미 정해져 있다. 만약 정해지지 않았다면 `isTabletAtLaunch()` 가 `false` 를 내어 **1단으로 떨어질 뿐 깨지지는 않는다.**

### 실측이 계획을 고쳤다 — `values-sw900dp` 신설

1.6배(`sw720dp`)로 올려 화면을 재 보니 **내용이 가용 높이의 68% 만 썼다.**

| | 1.6배 | **2.0배 (신설)** |
|---|---|---|
| 두 열이 쓰는 높이 | 445dp | 562dp |
| 빈 띠 | **245dp** | **106dp** |
| 가용 761dp 중 사용률 | 68% | **85%** |

계획의 «가용 높이 708dp» 가정이 틀렸다. 실제는 **829dp**(`h829dp`)이고, 툴바 56dp 와 패딩 12dp 를 빼면 **761dp** 다. 그만큼 여유가 더 있었다.

`values-sw900dp` 를 더해 글자 11→22dp · 12→24dp, 버튼 30→**64dp** 로 올렸다. 이 값은 계산이 아니라 **실측에서 나왔다.**

## 재작업 (2026-08-26 17:57) — 은수님 지시로 배치를 다시 짬

첫 안(전폭 헤더 + 2열 + 전폭 푸터)을 물렸다. 새 규칙은 두 가지다.

| 지시 | 반영 |
|---|---|
| 사용자 이름 · 시리얼 · 버전 정보를 **왼쪽 화면**으로 | 전폭 헤더를 없애고 왼쪽 화면 맨 위로 |
| `Caution` 을 **오른쪽 화면**으로 | 전폭 푸터를 없애고 오른쪽 화면 맨 아래로 |
| `Buttons` → **`OTA Features`** | 레이아웃 텍스트라 **폰·태블릿 공통** |
| `Etc,...` 를 **하단에 붙이고** 그 위에 `Remote` | `Etc` 를 `parent.bottom` 에, `Remote` 를 그 위에 |
| `List of slots` 를 `Cur` 과 **같은 높이**에서 시작 | `TOP → 상태 격자.TOP` |
| `OTA Features` 를 `Remote` 와 **같은 높이**에서 | `TOP → Remote.TOP` |
| `Caution` 을 `Etc,...` 와 **같은 높이**에서 | `TOP → Etc.TOP` |

### 세로 체인을 버렸다

오른쪽 묶음들이 **서로가 아니라 왼쪽 묶음을 기준으로** 서기 때문이다. 체인은 «앞뒤가 서로를 문다» 는 구조라 이 배치를 표현하지 못한다. 윗변끼리 묶고(`TOP → TOP`) 아래쪽은 묶지 않는다 — 묶으면 내용이 눌리거나 잘린다.

### 실측 정렬 확인

| 왼쪽 | 오른쪽 | 차이 |
|---|---|---|
| 상태 격자 `Cur` y=179 | `List of slots` y=177 | **2px** |
| `Remote` y=628 | `OTA Features` y=628 | **0px** |
| `Etc,...` y=840 | `Caution` y=838 | **2px** (버튼 행은 875 로 동일) |

2px 은 글자 모양 차이다(`Etc,...` 의 쉼표 내림획). 상자 윗변은 같다.

`Etc` 바닥과 프래그먼트 바닥의 여백은 **2.3dp** — 지시대로 «하단에 붙었다».

## 2차 재작업 (2026-08-26 18:14) — 여백과 세로 정렬

| 지시 | 반영 |
|---|---|
| 태블릿 상/하/좌/우 **패딩을 더** | 루트 패딩을 `tdc_screen_padding_h`·`_v` 로 빼고 한정자별로 키움 (폰 8/6 → sw900 **24/16dp**) |
| `List of slots` 를 이름 아래 ~ `OTA Features` 사이 **세로 중앙** | `List of slots` + `Status of files` 를 **세로 체인(packed, bias 0.5)** 으로 묶어 그 구간 가운데에 세움 |
| `Cur` 을 `Status of files` 위치에 | `상태 격자.TOP → Status of files.TOP` |
| **왼쪽/오른쪽 화면 사이 마진만큼 모든 버튼 사이에** | `tdc_button_gap` 하나로 모음. 버튼 26곳(가로 22 · 세로 4)이 이 값을 쓰고, **열 사이 간격은 코드가 이 값을 절반씩 나눠 양쪽에 준다** |

### 기준이 뒤집혔다

1차에서는 «왼쪽이 자리를 정하고 오른쪽이 따라갔다»(`List of slots.TOP → 상태 격자.TOP`). 2차는 반대다 — **오른쪽 위 덩어리가 가운데에서 자리를 잡고 왼쪽 상태 격자가 따라간다.** 1차 방식은 오른쪽 덩어리가 위로 쏠려 아래에 큰 빈 띠를 남겼다.

### 간격을 한 값에서 끌어온 이유

«열 사이» 와 «버튼 사이» 가 같아야 화면이 한 격자로 읽힌다. 두 곳에 따로 적으면 반드시 어긋난다. 그래서 코드가 `R.dimen.tdc_button_gap` 을 읽어 `/2` 한 값을 양쪽 열에 준다.

### 실측 (Galaxy Tab A8 10.5)

| 왼쪽 | 오른쪽 | 차이 |
|---|---|---|
| 상태 격자 `Cur` y=306 | `Status of files` y=304 | **2px** |
| `Remote` y=589 | `OTA Features` y=589 | **0px** |
| `Etc,...` y=814 | `Caution` y=812 | **2px** |

세로 중앙 — 이름 아래(178) ~ `OTA Features`(589) 구간에서 덩어리가 219..544. **위 41px / 아래 45px.**

간격 — 버튼 행을 가로로 훑어 **7개 간격이 전부 16px = 12.0dp**. 열 사이도 같은 16px. 화면 좌우 여백 32px = 24.0dp.

### 폰트는 줄이지 않았다

은수님이 *"필요하다면 폰트 크기를 지금보다 살짝 줄여도 돼"* 라 했으나 **재 보니 필요가 없었다.** 상태 격자 바닥(480)과 `Remote`(589) 사이 109px, 오른쪽 덩어리 바닥(544)과 `OTA Features`(589) 사이 45px 로 여유가 있고 잘린 글자가 없다. 필요 없는데 줄이면 나빠진다.

## 3차 재작업 (2026-08-26 18:24) — 줄 맞춤과 간격

| 지시 | 반영 |
|---|---|
| 버튼 **세로** 사이에도 가로와 같은 마진 | 2차에서 **거꾸로 들어가 있었다** — 첫 버튼 행에만 붙고 정작 행 «사이» 3곳에는 없었다. 3곳에 추가 |
| 폰트를 아주 조금 축소 | `sw900dp` 기준 22→20 · 24→22 · 28→24 · 36→30dp |
| `REL` 은 왼쪽 화면 오른쪽 끝 | 유지 (실측 x=951 로 열 끝에 정확히 붙음) |
| 제조번호를 이름 끝에서 마진 두고 | ID 박스를 **평평하게 재구성** |
| 사용자 정보 세로 중앙 | 배지의 `layout_gravity` 를 `top` → `center_vertical` |
| `BT↔Name` · `Nop↔MFST` · `Frm↔APP0` · `Prog↔APP1` | 두 격자의 행 높이를 **`tdc_status_row_height` 로 통일** |

### ID 박스 — 폭을 나누지 않는다

예전에는 이름과 «제조번호+배지» 가 화면을 **절반씩 나눠** 가졌다. 이름이 짧으면 제조번호가 화면 한가운데에서 시작해 이름과 동떨어져 보인다.

바꾼 뒤에는 이름이 제 글자만큼만 차지하고, 제조번호가 간격을 두고 바로 붙으며, **남는 폭을 제조번호가 먹어** 배지가 자연히 오른쪽 끝에 선다. 셋 다 `center_vertical` 이다.

### 행 높이를 왜 고정했나

두 격자는 글자 크기가 다르다(상태 격자 `small`, 파일 목록 `normal`). `wrap_content` 로 두면 **첫 줄만 맞고 아래로 갈수록 어긋난다** — 실측으로 왼쪽 37px, 오른쪽 44px 였다. 같은 고정 높이를 주면 글자 크기가 달라도 줄이 나란해진다.

### `MaterialButton` 의 세로 inset

세로 간격을 12dp 로 주었는데 **보이는 간격은 15dp** 였다. 버튼마다 `insetTop`·`insetBottom` 이 `2dp` 씩 있어 마진에 4dp 가 더해졌기 때문이다(가로 inset 은 0 이라 가로만 정확했다).

**inset 을 0 으로 두고 간격을 마진 하나로만 통제한다.** 그래야 «한 값에서 끌어온다» 가 실제로 성립한다. 버튼의 보이는 높이가 4dp 커지지만 레이아웃 높이는 그대로다.

## 4차 재작업 (2026-08-26 18:33) — 크기와 사용자 표기

| 지시 | 반영 |
|---|---|
| 전체 폰트·위젯 **1단계** 축소 | 태블릿 3단을 함께 내림. `sw900` 기준 글자 18/20/22/24 → **16/18/20/22dp**, 버튼 64→**56dp**, 행 32→**29dp** |
| 이름·시리얼 **2단계** 축소 | 이름 30→**26dp**, 시리얼 24→**20dp** |
| 이름 옆에 착용 위치 (L·R·F) | `UtilUser.makeDisplayName()` 신설 — «공장초기화 **왼쪽** #1A5FFFFF» |
| 시리얼 자간 기본으로 | `letterSpacing="0.14"` 제거 |

### 시리얼에 전용 크기를 준 이유

시리얼과 **연결 화면 제목**이 `tdc_text_size_large` 를 함께 쓰고 있었다. 시리얼만 2단계 줄이라는 요구를 그대로 따르면 연결 화면 제목까지 줄어든다. `tdc_text_size_isd_id` 를 따로 뺐다.

### 착용 위치가 왜 안 보였나

표기 로직이 **여섯 곳에 흩어져** 있었고, 모두 «별명이 있으면 별명만, 없으면 이름(착용위치)» 였다. 지금 사용자는 별명이 «공장초기화» 라 착용 위치가 빠졌다.

같은 사람의 좌/우 기기를 화면에서 구분할 수 없다는 뜻이라 결함이다. `UtilUser.makeDisplayName()` 하나로 모으고 **별명이든 이름이든 착용 위치를 붙인다.** 괄호는 없앴다(은수님 예시 «토닥 초기화 #12345678»).

`getEarKorean()` 이 이미 `L`·`R`·`F` → 왼쪽·오른쪽·초기화 를 하고 있어 새로 만들 것이 없었다.

## 배경색 — 앱이 아니라 기기였다

은수님 *"예전하고 백그라운드 색상이 좀 다른거 같지? 살짝 밤색 느낌이야"*

**앱은 색을 바꾼 적이 없다.** 근거 넷.

| 근거 | 결과 |
|---|---|
| git | `colors.xml`·`styles.xml` 무변경. `values/` 에서 바뀐 것은 `dimens.xml` 뿐 |
| 리소스 값 | 화면 배경 `white_10` = `#FF191919` = **순수 회색 (25,25,25)** |
| 재작업 전후 대조 | 배치를 바꾸기 전(`tab_03`)과 후(`tab_06`) 모두 **(57,45,21)** 로 동일 |
| **필터를 끈 뒤** | `tab_07` 배경이 **(25,25,25)** — 리소스 값과 정확히 일치 |

원인은 **삼성 블루라이트 필터**였다(`settings get system blue_light_filter` 가 `1` → 지금은 `0`). 순수 회색이 갈색으로 틀어져 보인 것이고 캡처에도 그대로 들어갔다.

> [!TIP]
> **화면 색이 이상하면 앱을 뒤지기 전에 기기 설정을 본다.**
> `adb shell settings get system blue_light_filter` · `screen_mode_setting` ·
> `adb shell dumpsys color_display`.

### 배지를 상자 밖으로 뺀 이유

배지가 `ota_id_box`(사용자 정보 줄) **안**에 있으면 그 상자를 벗어나 오른쪽 화면으로 옮길 수 없다. 루트의 직계로 빼고, **폰에서는** 사용자 정보 줄 오른쪽 끝에 붙도록(`Bottom/Top → ota_id_box`) XML 제약을 걸었다. **태블릿에서만** 위치를 바꿔 건다. 폰 화면은 지금과 같다.

### 착용 위치를 `Spannable` 로 만든 이유

한 `TextView` 안에서 **부분만** 다른 크기·색을 칠해야 한다. `SpannableString` + `AbsoluteSizeSpan` + `ForegroundColorSpan` 을 이름 뒤(` - 착용위치` 구간)에만 걸었다. `makeDisplayName()` 이 `Context` 를 받도록 바뀌어 호출부 3곳에 `Context` 를 넘겼다(`MainActivity.this` · `requireContext()`).

## 6차 재작업 (2026-08-26 18:46~19:00) — 연결 오버레이 테두리, 절 사이 여백

### 연결 오버레이가 화면 끝까지 안 덮이는 문제

은수님 *"외부기를 머리에 부착한 상태에서... 이거 레이아웃의 패딩 적용되어서 실제로 화면 상에서는 상/하/좌/우에 검정색 테두리처럼 보여지는 상황"*

**원인 2단**

1. 오버레이(`remote_control_connection_layout`)가 루트 `ConstraintLayout` 의 자식이라 `layout_constraintTop_toTopOf="parent"` 가 **부모의 패딩 안쪽**을 가리킨다. 패딩을 키운 태블릿에서 그 패딩만큼 테두리가 남았다
2. **1차 시도**(패딩만큼 음(-) 마진)만으로는 위치는 옮겼지만 **여전히 안 보였다.** `ViewGroup` 기본값 `clipToPadding = true` 가 자식의 «그리기» 자체를 패딩 안쪽으로 잘라내기 때문이다 — 부모 자신의 배경은 이 클리핑을 안 받아 패딩 자리에 그대로 남았다

**고친 것** — `extendConnectionOverlayToEdges()` 신설. 오버레이에 `-tdc_screen_padding_h`·`-tdc_screen_padding_v` 마진을 주고, **그 부모의 `clipToPadding` 을 끈다.** 값은 루트가 쓰는 것과 같은 dimen 에서 읽어 드리프트가 안 나게 했다.

실측 — 모서리(20,150)·(1900,150) 모두 `(70,70,70)`(오버레이 색)로 균일. 이전에는 `(25,25,25)`(배경 그대로)였다.

### 절 제목과 이전 절 마지막 행 사이 여백

은수님 *"Remote 와 Program- 사이의 간격 만큼, Out-와 Etc,... 사이에도 최소한 그 이상의 마진이 필요해 보이거든? 다른 항목들도 마찬가지고 말이야."*

**원인** — 절 제목(`Remote`·`Etc,...`·`OTA Features`·`Caution`)이 **자기 다음 행**과의 간격(`tdc_button_gap`)은 갖고 있었지만, **자기 앞 절**과의 간격은 `marginTop` 자체가 없어 `0` 이었다. 넷 다 같은 결함이었다.

**고친 것** — 네 제목 `TextView` 에 `android:layout_marginTop="@dimen/tdc_button_gap"` 을 추가했다. 폰·태블릿 공통(XML 기본값이라 한 벌).

**실측** (왼쪽 화면) — `Remote`→`Program-` 21px(15.8dp) 대비 **`Out-`→`Etc,...` 23px(17.3dp)**. 요구한 «최소한 그 이상» 을 충족한다.

> [!NOTE]
> **오른쪽 화면의 `OTA Features`·`Caution` 은 이 여백이 눈에 잘 안 띈다.** 두 절이 **왼쪽 화면의 높이를 따라 정렬**되도록 설계돼 있어(계획 §판단_1), 그 정렬이 만드는 공백(약 100px)이 이번에 추가한 12dp 여백을 가린다. 결함이 아니라 다른 규칙이 앞서는 것이다.
