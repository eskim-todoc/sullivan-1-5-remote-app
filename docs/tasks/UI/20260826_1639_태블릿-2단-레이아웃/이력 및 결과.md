# 이력 및 결과

**TL;DR**: 태블릿 가로에서 남는 공간을 내용이 아니라 여백만 먹어 위젯이 화면 끝에서 끝까지 흩어지는 문제를 고친다. 세로 체인 `packed` · 태블릿 전용 치수 · 제어/OTA 두 열 분할을 한 번에 적용한다. 지금은 계획 검증까지 마치고 승인을 기다린다.

## 결정 기록

| 결정 | 내용 | 근거 |
|---|---|---|
| 열 분류 기준 | 화면 이등분이 아니라 **«제어의 종류»** | 은수님 지시. 두 일을 동시에 하지 않으므로 눈이 한 열에만 머문다 |
| 헤더·푸터를 두지 않는다 | 기기 정체는 왼쪽 화면, `Caution` 은 오른쪽 화면 | 은수님 지시(2026-08-26 재작업). 전폭 띠가 두 화면을 가로질러 «한 덩어리» 로 읽히는 것을 없앴다 |
| 오른쪽은 왼쪽 높이를 따른다 | `TOP → TOP` 세 쌍 | 두 화면이 나란한 줄로 읽히게 한다. 그래서 세로 체인을 버렸다 |
| 세 갈래 동시 적용 | ①②③ 을 한 작업으로 | ③ 만 하면 세로가 더 남아 허전해진다(분석 §3.3). ② 가 그 공백을 메운다 |

## 완료 요약

**바뀐 것** — `values/dimens.xml`(치수 6개) · `values-sw600dp/dimens.xml`·`values-sw720dp/dimens.xml`(신설) · `fragment_remote_control.xml`(112곳 치환 + `Guideline`) · `MainActivity.java`(접근자 1개) · `RemoteControlFragment.java`(2단 배치 메서드 4개).

**핵심** — 8묶음이 이미 루트의 형제라 계층을 바꾸지 않고 제약만 다시 걸었다. 그 덕에 **레이아웃 파일이 한 벌**로 남고 **바인딩 참조 120곳을 한 곳도 건드리지 않았다.**

**남은 것** — 실기 확인 6건([`구현-검증.md`](구현-검증.md) §실기로만 남는 것). 특히 **연결 오버레이가 정상 표시되는지**가 이 방식의 유일한 위험이다.
