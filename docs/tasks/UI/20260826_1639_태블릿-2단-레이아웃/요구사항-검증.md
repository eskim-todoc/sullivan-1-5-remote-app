# 요구사항 검증

**TL;DR**: 요구사항 7건과 미결 2건을 지침 준수·논리 정합·근거 세 축으로 검증했다. 근거는 모두 파일·라인으로 확인했고, 태블릿 판정 기준이 `values-sw600dp` 한정자와 같은 조건이라는 사실을 새로 확인해 요구사항_2 의 실현 가능성이 올라갔다. 미결 2건은 남긴 채 잠정안으로 진행한다.

## 축_1 — 지침 준수

| 항목 | 판정 | 비고 |
|---|---|---|
| 라벨링 (알파벳 약어 금지) | 통과 | `요구사항_1`~`요구사항_7` · `미결_1`~`미결_2` 한글 라벨 |
| frontmatter 4필드 + TL;DR | 통과 | `name`·`purpose`·`type`·`tags` · TL;DR 158자 |
| 다이어그램 Mermaid | 해당 없음 | 요구사항 문서에 다이어그램 없음 |
| 확신도 구분 (`기억/은수님.md` §3) | 통과 | 해상도는 «가정», 배율은 «계산이지 실측이 아님»으로 명시 |
| 모호하면 질문 (헌법 §2) | 통과 | 미결 2건을 질문으로 남기고 잠정안을 함께 제시 |

## 축_2 — 논리적 정합성

| 검사 | 판정 | 내용 |
|---|---|---|
| 요구사항_2 ↔ 제약(세로 넘침) | **충돌 가능** | 내용을 키우면 세로가 넘칠 수 있다. **분석에서 높이 예산을 세워 배율 상한을 정해야 한다** |
| 요구사항_3 ↔ 요구사항_6 | 정합 | 2단은 태블릿 한정(`layout-sw600dp`), 폰은 기존 `layout/` 을 그대로 쓴다 |
| 요구사항_4 ↔ 요구사항_3 | **긴장** | 2단을 만들려면 레이아웃 파일이 둘인데 본문은 한 벌이어야 한다. `<include>` 로 위젯 정의를 떼어내야만 둘 다 성립한다 |
| 요구사항_7 ↔ 요구사항_4 | 정합 | `<include>` 는 자식의 `id` 를 그대로 유지하므로 `findViewById` 가 깨지지 않는다 |
| 요구사항_1 ↔ 요구사항_3 | 정합 | 세로 체인은 두 레이아웃 모두에 적용된다. 2단에서는 각 열 안의 세로 체인에 적용 |
| 미결_2 잠정안 ↔ 요구사항_3 | 정합하나 대가 있음 | 쪼개면 «제어의 종류» 축은 깨끗해지지만 «위험한 동작 한군데» 라는 다른 안전 장치를 잃는다. 요구사항 §3 에 반대 근거를 명시함 |

> [!WARNING]
> **미해결로 남기는 것**: 요구사항_2 의 배율 상한은 이 단계에서 정할 수 없다. 분석에서 높이 예산을 계산한 뒤 계획에서 확정한다.

## 축_3 — 근거 검증

| 주장 | 근거 | 판정 |
|---|---|---|
| 폰/태블릿을 판별해 방향을 고정한다 | `MainActivity.java:314` `TABLET_MIN_SMALLEST_WIDTH_DP = 600` · `:334` 태블릿 `SCREEN_ORIENTATION_LANDSCAPE` / 폰 `PORTRAIT` | **코드로 확인** |
| 태블릿 판정과 `sw600dp` 한정자가 같은 조건 | `MainActivity.java:324` 가 `config.smallestScreenWidthDp` 를 쓴다. `values-sw600dp` 한정자도 같은 값을 본다 | **코드로 확인** |
| 최상위 묶음 8개가 전폭·세로 체인 | `fragment_remote_control.xml` 의 8개 `LinearLayout` 이 모두 `width=0dp` + `start/end→parent`, `Top_toBottomOf`/`Bottom_toTopOf` 로 연결 | **파일로 확인** |
| `chainStyle` 미지정 | `grep chainStyle` 결과 0건 → 기본값 `spread` | **파일로 확인** |
| 버튼 높이 `30dp` 25곳 | `grep -c 'layout_height="30dp"'` = 25 | **파일로 확인** |
| 글자 크기 하드코딩 87곳 | `11dp` 45 · `12dp` 38 · `14dp` 2 · `18dp` 1 · `10dp` 1 = 87 | **파일로 확인** |
| `values-sw600dp` 에 치수 없음 | 폴더에 `toolbar_navigation_message.xml` 만 존재 | **파일로 확인** |
| Android 권장 최소 터치 타깃 48dp | Material 접근성 지침 | **문서로 확인** (인쇄물 근거, 코드 아님) |
| 태블릿 1280×800dp | 근거 없음 | **가정** — 요구사항 §4 에 가정으로 표기함 |
| `Caution` 버튼 둘의 성격이 다르다 | `ota_factory_reset_button`(`FW slot rollback`) · `ota_map_init_default_button`(`Map rollback`) | **파일로 확인** |

## 결론

**요구사항 문서를 그대로 다음 단계로 넘긴다.** 다만 두 가지를 분석에서 반드시 푼다.

1. **높이 예산** — 배율 상한을 계산으로 확정 (축_2 충돌)
2. **`<include>` 분해 범위** — 어느 묶음을 파일로 뗄지 (축_2 긴장)
