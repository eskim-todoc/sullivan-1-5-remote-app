## 목표와 범위

초기에는 docs/참고/TodocON_Android_UI_Reference.zip을 기준으로 가로 전용 안을 만들었으나, 사용자 요청에 따라 **기존 세로 앱에 더보기·등록·로그 등의 관리 화면을 합치는 방향**으로 바꿨다. 확정 시안을 실제 네이티브 앱의 BLE·Room·OTA 흐름에 적용하고 연결 휴대전화와 REL4.5 보드로 검증한다. 현재 브랜치는 develop_ota_landscape, 기준 커밋은 130037c다. 장치 신원 변경·맵 초기화·공장 맵 복원은 실행하지 않는다. 일반 제어·화면 흐름과 후속 요청한 OTA 실제 전송·슬롯 부팅·공장 펌웨어 복귀를 시험한다.

최신 구현 결과는 이 문서 하단의 실제 앱 검증과 [실기 기본 제어](native/screens/final-basic.png)다. [세로 통합 갤러리](preview/portrait/index.html)와 [직접 미리보기](preview/portrait/app.html)는 확정 시안이며 예시값으로 동작한다. 아래 가로·세로 시안의 분석과 검증은 당시 기록으로 보존한다. 전체 화면 가로 셸의 추가 조정은 세로 전환 요청으로 대체되었다.

## 수용 기준

1. 제공한 각 화면의 정보 구조·기능을 기존 Android 구현과 대응하고 미구현 기능을 구분한다.
2. 최신 세로 시안은 기존 상태 순서와 기본 제어·특수 제어·FF·OTA 탭을 유지하고, 다섯 번째 더보기에 등록·장치 관리·로그를 통합한다. 3점 배경·유리 면은 기존 앱을 따른다.
3. 연결 휴대전화의 세로 앱 영역 약411×781dp에서 기본 제어와 더보기가 한 화면에 들어오고, 긴 목록·설정·로그는 세로로 스크롤한다. 가로 넘침과 상태 라벨/값의 겹침이 없어야 한다.
4. 제조번호/페어링키, 맵 시험 초기화/공장 맵 복원/공장 펌웨어 부팅을 실제 프로토콜에 맞게 구분한다.
5. 새 REL4.5 배터리 index2·구형 응답 fallback·전류/전력의 유효성 정책을 정리한다.
6. 미리보기·예시값과 실제 BLE 구현 완료를 혼동하지 않도록 표시하고 검증 근거를 남긴다.

### 구현 구조·권장 순서

1. 네이티브 가로 Shell + 좌측 장치/우측 메뉴 + 선택 장치 상태를 만들고 기존 단일 장치 제어·등록·OTA/로그 연결. 가로 고정은 기존 applyScreenOrientation의 폰/태블릿 분기를 변경하는 지점이다.
2. Battery capability는 FF/Maximum capability와 분리한다. 55/56/57 등 신원·복원 명령에는 일반 명령의 자동3회 재전송을 적용하지 않는다. 명령 한 번 → 되읽기/완료 응답 → 재연결/검증으로 진행하고 응답 유실은 적용 여부 미확인으로 보존한다. 새 키는 마스킹하고 새 키 적용 후 실제 인증이 될 때만 앱 등록 키를 완료 상태로 전환한다.
3. 현 단일 BluetoothGatt, Status.instance, 단일 StatusViewModel/Ota/timeout/transferState를 DeviceSession 단위로 나눈 뒤 오디오 수집과 동시 관찰을 연결한다. UI 카드 여러 개만 추가하면 다른 장치로 명령이 전송될 수 있다. OTA/FF와 측정·주기 조회는 장치별 큐에서 우선순위·양보를 정한다.
4. 정적인 3점 배경은 한 장의 흐린 원본 레이어를 재사용하고 카드의 둥근 클립·반투명 받침·테두리·하이라이트를 일치시킨다. Android 기존 application.hardwareAccelerated=false는 실제 구현에서 성능 대조 대상이며, debug 미리보기 Activity에만 true를 명시했다. blur API 의존을 피한 캐시 배경/폴백이 구형 기기까지 동일 외형을 내는 출발점이다.

fw_contracts의 배터리 index2 및 네 종류의 맵/펌웨어 명령 구분, identity_contracts의 독립55/56과56 후재초기화, android_mapping의 기존 기능 재사용·오디오/다중연결 신규 구조를 채택했다. 세 조사자는 읽기 전용으로 반환했고 변경 파일이 없다. 주요근거는 현재 로컬 작업트리 기준으로 통합했다. 후속 UI 심사의 좁은 수정은 루트 소유 파일에만 반영했다.

## 이전 개정 — 휴대전화 가로에 맞춘 재구성

아래는 직전 축약 상태 시안의 기록이다. 전체 상태를 버튼으로 여는 방식과48px 제어 크기는 다음 개정에서 대체했다. 최신 화면·검증은 문서 마지막 절과 preview/phone을 기준으로 본다.

### 판단과 변경

사용자가 PC식 구성, 설명 줄바꿈, 긴 화면의 스크롤을 비판적으로 재검토하도록 요청했다. 연결 기기의 화면은 2280×1080 출력 / density420이며 카메라 안전 영역 104px를 제외한 실효 폭이 약828dp다. 전체 물리 폭868dp를 그대로 사용하지 않았다.

루트가 `preview/phone/`와 debug 미러를 소유하고, `preview_review`는 시각 계측, `phone_ux_review`는 과업 흐름을 읽기 전용으로 검토했다. 기존 `preview/app.*`·태블릿 레이아웃과 실제 MainActivity/BLE/Room은 보존했다.

- PC 브랜드 제목줄과 왼쪽 장치 레일을 제거. 장치 선택 FFFF, 사용자·착용 위치, 내부기 번호, 연결·REL을 48높이 상단 영역에 통합했다.
- 고정 상태 띠에 배터리·소비 전류·소비 전력·Current PMIC를 독립 라벨/값으로 배치했다. 전체 상태는 명시적인 버튼으로 열며 본문을 아래로 밀지 않는다.
- 오른쪽 고정 메뉴는 기본 제어 / 특수 제어 / FF / OTA / 더보기. 장치 관리·등록·관찰·로그는 넓은 더보기 항목으로 진입한다. 메뉴 텍스트가 두 줄로 나뉘지 않는다.
- 특수 제어 PMIC / 링크·통신과 장치 정보 / 맵 관리, OTA 업데이트 / 슬롯·복구를 분리했다. 6개 설정 타일 또는 4개 맵 타일로 한 화면에 작업을 끝낸다.
- 등록은 목록 → 편집으로 전환하고 상단에 저장을 고정했다. 편집 초안·등록 목록·현재 연결 신원을 분리해 다른 사용자를 편집하는 도중 연결 신원이 바뀌지 않는다.
- 상시 설명은 한 줄 목적·영향으로 압축했다. 긴 도움말은 항목 가까운 도움말, 맵/부팅 등 영향 설명은 실행 직전 확인창에 둔다. 확인창과 외부기 정보 변경의 의미는 이전 프로토콜 분석을 유지한다.
- 글자를 일괄 축소하지 않고 주요 라벨13~14, 값16~18, 보조11~12를 사용했다. 버튼/입력은 48이상 영역을 확보했다. PMIC 타일의 지원/미지원 값 행은 같은 높이로 맞췄다.

시각 검토의 타일 값/설명 기준선 정렬과 중복 저장 안내 제거를 채택했다. UX 검토의 초안/현재 신원 분리, 설정 재진입 때 현재값 표시, OTA 진행 예시의 중지 경로·변경 잠금을 반영했다. 루트가 변경 후 브라우저와 Android에서 재검증했다. 점수는 내부 의견이며 객관적 사용성 개선률로 사용하지 않았다.

새 미리보기는 실제 Android 네이티브 화면 구현을 대체하지 않는다. FF 전체 항목·진단·구간 보정표와 다중 장치 제어의 상세 구현은 다음 단계다. 이번에도 실제 장치 초기화·제조번호/키 쓰기·OTA 전송은 실행하지 않았다.

다시 실행: `render-phone-preview.cjs`, `validate-phone-gallery.cjs`. Android 실행은 기존 명령에 `--es design phone`을 추가하고 필요하면 `--es section maps` 또는 `--es edit user`를 지정한다. debug Activity의 Android 뒤로가기는 모달 닫기 → 편집 목록 → 더보기/기본 화면 → Activity 종료 순으로 동작한다. 최종 연결 휴대전화는 개선된 기본 제어 미리보기를 표시한다.

## 후속 요청 — 전체 상태 상시 표시와 버튼 축소

### 변경과 판단

사용자는 전체 상태를 열어야 확인하는 점과 큰 버튼을 지적했다. 상태 확인을 위해 누르거나 탭을 바꾸는 동작을 없애고, 설정 중 현재값을 계속 확인하는 구조로 개정했다. 큰 설정 카드의 값·설명을 상단 상태와 편집기로 옮겼다. 이전 축약 시안은 [phone-compact](preview/phone-compact/app.html)에 비교용으로 보존했다.

- 상단 상태140px에 자극 / 링크 백텔 / PMIC / 배터리·FF를 각각6행, 총24항목으로 표시한다. 값·라벨은12px, 라벨과 값의 겹침 없이 우측값을 정렬했다. 전체 상태 버튼·숨은 가로 스크롤을 제거했다.
- 아래 작업영역은728×191px. 일반 버튼 외관36px, 주 조작 터치44px로 분리했다. 일부 보조 버튼은36~40px이며 전체48px 접근성 기준 충족으로 표현하지 않는다.
- 특수 제어11개를 PMIC6 / 링크5로 한 화면에 표시한다. PMIC는 Normal·Fixed·Step을 위에, 드문 Mapping·Accel·Maximum을 아래에 둔다. 그룹을 바꾸는 추가 탭을 없앴다.
- 설정을 누르면 아래 작업영역만 편집기로 전환한다. 위 현재값은 초안 변경·취소 중 유지하고 적용 후 갱신한다. 숫자±와 On/Off 직접 선택으로 키보드가 상태를 덮지 않게 했다. 적용한 행만 잠깐 강조한다.
- 기본 제어± 위에 현재값을 한 줄로 덧붙였다. 기본/오디오/특수/편집의 카드 여백과44px 제목 영역을 맞췄다. FF 설정 카드는76px로 제한하고, OTA 파일은2×2, 등록 폼은 키보드가 없을 때4열로 구성했다.
- 등록 문자 입력 중에는 상태·메뉴를 잠시 접어 편집 대상·저장을 유지한다. 이는 제어 설정 편집과 다른 화면이며, 모든 상태를 그대로 유지한다는 설명은 제어 화면 기준이다.

## 최신 개정 — 기존 세로 화면에 관리 기능 통합

### 변경과 판단

사용자가 가로보다 세로가 좋겠다고 방향을 바꾸고, 기존 앱에 더보기·등록·로그 등을 합친 예시를 요청했다. 기존 가로 결과는 보존하고 `preview/portrait/`를 추가했다. 루트가 자산과 debug Activity를 수정했으며 android_mapping, phone_ux_review, preview_review는 기존 화면 매핑·흐름·시각 정렬을 읽기 전용으로 검토했다.

### 적용한 화면과 동작

- 전체 서체는 IBM Plex Sans KR v5.0.0 Medium/SemiBold/Bold로 통일하고 SIL OFL 라이선스를 앱에 포함했다. 사용자 이름 → 착용 위치 → 외부기번호 → 내부기번호 → R4.5의 개별 배지와 전체 본문 스크롤, 고정 하단5탭을 적용했다.
- 기본 제어는 Program·Volume / Output·Indicator의2×2 구성이다. 버튼에 중복 숫자를 표시하지 않고 LED/Alarm도 일반 버튼으로 통일했다. 특수 제어는 한 유리 패널 안의3열이다. FF 미지원 문구는 FF 탭 안에만 표시한다.
- OTA는 업데이트 / 슬롯·복구로 나누고 MFST/APP0/APP1/APP2 명칭, 파일 읽기와 전송 크기, 대상 슬롯 안내를 표시한다. 전송 중 페이지 이탈을 차단하고 슬롯과 수집 파일 조건을 검사한다.
- 더보기에 사용자·외부기·제조번호/페어링키·맵·통신 로그를 통합했다. 하위 화면 사이 전환 탭과 중복 장치 상태를 제거했다. 편집 뒤로가기는 같은 종류 목록을 거쳐 더보기로 돌아간다. 저장·삭제 등의 버튼은 내용 아래에 둔다.
- 제조번호4자리와 페어링키6자리는 화면 내 입력과 형식 검사 후 변경한다. 55/56의 정확한 응답, 57의 완료 응답을 구분하며 신원/초기화 명령을 자동 재전송하지 않는다. 응답 유실은 적용 여부 미확인으로 남기고 재연결을 요구한다. 시험 맵 수락과 작업 완료도 구분한다.
- 맵4종은 영향 경고와 진행/취소로 구성했다. 제조번호 재입력은 없다. 공장 맵·설정 복원과 OTA 공장 펌웨어 부팅은 별도 기능으로 유지한다. 사용설명서 메뉴와 화면 잠금 동작은 제거했다.
- 로그는 최신 기록부터 표시하고 검색·분류·내보내기를 제공한다. 인증·페어링키 내용은 마스킹한다. 내보내기는 선택한 기록을 먼저 앱 캐시에 보관하고 파일 선택기 복귀 시 원본 확인 후 목적지를 연다.
- 상태/관리 패널에 얕은 elevation을 적용했다. 다이얼로그에는 흐린 배경 캡처 폴백, 반투명 어두운 받침, 윗테두리 반사광과12dp 그림자를 공통 적용했다. 지원 기기에서는 시스템 blur도 사용한다. 배경 글자는 흐리게 남기면서 본문은 선명하게 표시한다.

## 후속 색상 검토 — 밝기와 붉은빛

## OTA 실제 시험 후속 요청

사용자가 “OTA 테스트도 가능?”이라고 요청해 실제 전송·부팅 시험의 사전 확인을 시작했다. 기존 UI·파일 읽기 시험만 완료된 상태와 구분한다. 대상은 계속 같은 휴대전화 R3CM7068Y6P와 미착용 시험 보드FFFF다. 새 색상은 적용하지 않는다.

사전 상태: REL4.5, 배터리70%/약3.95V, Program1/Volume1/Output4, GatingOff/LEDOn/AlarmOn, Step4/FixedOff. 새 C2 01 응답도 C2 01 01 00 01 FF FF로 확인했다. 이는 부트 상태 형식0.1, 현재·이전 모두 공장 이미지FF라는 뜻이다. UI의255 표시는0xFF의10진수 표시다.

폰에는 OTA/REL4.4만 있다. 폴더명을 버전 근거로 삼지 않고 네 파일의 크기·SHA를 읽어 대조했다. 로컬 REL4.5 저장소의 기존 fw-downloader/ez8300/fw_rel-4-5-0-full-8mb.hex 안에서 동일 버전 OTA 묶음을 확인했으므로 새 펌웨어 빌드·REL4.4 다운그레이드 없이 해당 산출물에서 추출할 계획이다. 원래 폰의 REL4.4 폴더는 보존한다.

시험 경로: 이미지 체크섬·파일 묶음 확인 → 별도 폰 폴더에 복사·해시 대조 → 앱 Collect → 공장FF를 보존하고 슬롯2에 MFST/APP0/APP1/APP2 전송 →100%와 RTT 쓰기 결과 확인 → 슬롯2 부팅 → 재연결·REL4.5·상태 조회·가역 제어 확인 → 공장FF 복귀와 재연결 확인. OTA 중 탭 이탈 차단도 실제로 확인한다. 맵·사용자 설정 초기화나 제조번호·키 변경은 하지 않는다.

코드 대조: 정상 쓰기는 슬롯1/2만 가능하고 현재 부팅 슬롯을 거절한다. 전송 ACK100%는 전체 CRC 검증을 뜻하지 않으며 부팅 로더가 FEZ 헤더·섹션 CRC를 검사한다. 공장FF는 OTA 쓰기로 덮지 않는다. 자동 롤백3회 정책은 소스 근거이며 이번 시험에서 실패 부팅·전원 차단을 주입하지 않는다. 기존 파일을 truncate하지 않는 펌웨어 경로가 있어, 슬롯 기존 크기/읽기 지원 확인과 실제 부팅 검증을 함께 판단한다.
