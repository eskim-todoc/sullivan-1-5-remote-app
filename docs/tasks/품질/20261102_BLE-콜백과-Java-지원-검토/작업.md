## 현재 코드와 역사적 근거
- b7f55a8 (2022-11-22): “onCharacteristicChanged 콜백에 Status의 큐를 활용하도록 develop 브랜치에서 코드를 패치하였음.” 변경 전에도 Handler(main).post는 있었다. 핵심 변화는 post 내부의 늦은 characteristic.getValue()를 없애고, 콜백에서 즉시 값을 queue에 offer한 후 main에서 poll한 점이다. 당시 예외/재현 로그가 없어 고장 원인은 확정할 수 없으나 수신 시점 값 보존과 밀접하다.
- 현재 MainActivity5515 구형 콜백 → 5527 packet.clone() → 2608 dispatchGattCallback → 세션 세대 guard/메인 Handler → 파싱/StatusViewModel.setValue → RemoteControlFragment3098 등의 LiveData observer → View 갱신.
- API26+ connectGatt(2828)에 main Handler를 명시한다. API23~25 또는 다른 스레드에서는 dispatcher가 한 번 post한다. 이미 main이면 즉시 처리해 먼저 들어온 ACK가 timeout 뒤로 밀리는 것을 막는다(SessionCallbackDispatcher17).

## 공식 API 대조
- API33부터 onCharacteristicChanged(gatt, characteristic, byte[] value)를 제공한다. 문서는 characteristic 객체 내부 값이 알림 이후 바뀔 수 있으므로 그 알림 시점의 value 인자를 사용하도록 안내한다. 기존 2인자 콜백은 deprecated이다.
- 현행 코드는 byte[] 복사로 옛 지연 읽기 문제를 피하고 있지만, API33 새 3인자 콜백 override는 아직 없다. 새 콜백에서 기존 공통 처리기로 value를 전달하고 구형 콜백은 API32 이하 호환용으로 유지하는 것이 최소 대응이다. deprecated는 즉시 삭제/동작 중단과 동일하지 않다.
- 현재 minSdk23 / compileSdk34 / targetSdk35 / Java source/target11. 이 정도의 API33 대응은 Kotlin 전환 없이도 가능하다.
- Android의 UI toolkit은 스레드 안전하지 않으며 UI 작업은 UI 스레드에서 실행해야 한다. 이 규칙은 Java와 Kotlin 모두 동일하다. Handler 자체를 버리거나 전체 콜백을 임의의 worker로 이동할 근거는 없다.
- 성능 후보: main parser 안에서 MainActivity2886 writeSessionLog → UtilLog141 writeLog/149 동기 Room 트랜잭션,104 allowMainThreadQueries를 사용한다. 고빈도·다중 GAIA에서 지연을 측정할 대상이다. 이번에 실제 지연을 재현/측정한 것은 아니며 현재 장애로 단정하지 않는다. 무거운 작업 분리 시 ACK/상태 직렬화와 LiveData.setValue의 main 계약은 보존해야 한다.

## Java 유지와 Kotlin 방향
- 2026-11-02 확인한 공식 Kotlin-first 문서는 Java의 Platform SDK, Android Studio, Lint, API/가이드 문서, AndroidX 지원을 Yes로 명시하고 Java API 사용 지원을 계속한다고 설명한다. 이 문서에는 Java 지원 종료일이 제시돼 있지 않다. 미래의 특정 연도까지 보장할 근거는 없다.
- Kotlin 전용 KTX/코루틴과 Compose 등의 새 기능은 Java 지원 표에서 제외된다. 공식 Compose-first 문서는 기존 View toolkit과 여러 View 기반 Jetpack/UI 도구가 유지보수 단계이며 주로 중요한 수정만 받는다고 설명한다. Java 언어 지원 종료와 별개의 UI 기술 방향이다.
- 권장안(저장소 구조에 근거한 판단): 기존 검증된 BLE/OTA Java는 유지하면서 신규 SOUND1/GAIA의 제품 프로파일·프로토콜 계층부터 Kotlin을 혼용한다. 이후 ViewModel/작은 모듈을 순차 전환한다. XML Views→Compose 교체는 별도 UI 프로젝트로 나누고 언어 변환과 한 번에 묶지 않는다. Java/Kotlin 혼용은 공식 지원된다.
